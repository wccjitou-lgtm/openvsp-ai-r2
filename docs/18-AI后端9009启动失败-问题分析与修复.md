# AI 后端 exit code 9009 问题分析与修复

**日期：** 2026-11-02  
**状态：** 已修复并重新打包  
**影响：** 其他电脑上 AI 设计 / GA 点“开始设计”立即 9009

## 1 审查结论

收到的《18-AI后端9009启动失败-问题分析与开发交接》定位正确：

- `ResolvePython()` 使用 `SearchPathW("python.exe")`，会命中 Windows Store 的 App Execution Alias；
- 别名的 `python.exe` 是 0 字节重解析点，`FileExists()` 仍返回 true；
- `StartDesign()` 只判空，未验证解释器真的能执行；
- 子进程 9009 秒退，只显示裸退出码。

此外，仅做路径黑名单也不够：还须拒绝 0 字节/重解析点、做一次真实版本和依赖探测。

## 2 已实施修复

### 2.1 内置 Python 运行时（根治安装环境）

- 在 `ai/python/` 内置 Python **3.13.3 embeddable amd64**；
- 安装 numpy / python-docx / matplotlib / pypdf / openpyxl / six；
- 添加 `Lib/site-packages` 和 `import site` 到 `python313._pth`；
- 安装包不再依赖目标电脑的 Python；
- 包体积从约 116 MB 增至约 161 MB，安装程序约 90 MB。

### 2.2 C++ 解释器解析

- `ResolvePython()` 候选顺序：
  1. `OPENVSP_AI_PYTHON`
  2. `APP_ROOT\ai\python\python.exe`（内置）
  3. `APP_ROOT\.venv\Scripts\python.exe`
  4. 已知 Python 3.13 目录
  5. 手工遍历 PATH（替换 `SearchPathW`）
- 每个候选执行 `IsUsablePythonPath`：
  - 拒绝 `Microsoft\WindowsApps` 路径；
  - 拒绝目录、0 字节、重解析点、不可读文件。
- 无效的 `OPENVSP_AI_PYTHON` 会记录并继续回退，不再静默使用别名。

### 2.3 启动前探测

点击“开始设计”前运行 `ProbePython()`：

- Python 3.13 版本校验；
- 检查 numpy/docx/matplotlib/pypdf/openpyxl/six；
- 8 秒超时；
- 失败时**不创建进程**，弹出中文修复说明（安装 Python、设置 `OPENVSP_AI_PYTHON`、关闭应用执行别名、运行 setup_ai_env.bat）；
- 成功后才写 `ai_job.json` 并启动后端。

### 2.4 退出码和停止状态

- 9009 / 0xC0000135 / 0xC0000139 / 0xC0000005 / 1 都有中文解释；
- 用户点“停止”后显示“已停止 AI 设计进程”，不再误报异常退出；
- 非零退出时提示输出目录和 result.json。

### 2.5 安装器 / MCP 提示词

- Inno Setup 的 `FindPython()` 优先使用安装目录的 `ai\python\python.exe`；
- `install_context.ini` 写入内置 Python 路径；
- `ShowMCPTutorial` 过滤不可用的 `PYTHON=` 行（例如旧安装器写入的 Store 别名）；
- MCP 提示词优先 `APP_ROOT\ai\python\python.exe`，再到 `.venv`、系统 Python 3.13；
- `setup_ai_env.bat` 优先内置运行时，并用 `python -c` 实跑校验，不再用 `where python` 直接信任。
