# OpenVSP 3.51.3-zh-CN R2 架构设计

> 版本：R2（2026-11-01）  
> 基座：OpenVSP 3.51.3 汉化版 R1 源码树（`work/OpenVSP-3.51.3-src`）  
> 目标：在 OpenVSP UI 内增加 **AI 设计模块**，让自然语言需求直接驱动 OpenVSP 建模、VSPAERO 计算、优化与报告生成；同时提供 **MCP 服务器**，供各类 Harness/Agent 直接调用 OpenVSP。

---

**职责划分**

| 层 | 技术 | 职责 |
|---|---|---|
| UI 壳 | C++ / FLTK 1.4 | 菜单、对话框、模型列表拉取（WinHTTP）、子进程生命周期、日志展示 |
| AI 后端 | Python 3.10+ | 大模型调用、工具循环、几何生成、VSPAERO 调度、优化、报告 |
| OpenVSP 内核 | C++/FLTK + VSPAERO | 几何内核、VLM 求解、导出 |
| MCP | Python stdlib | 将 OpenVSP 能力暴露为 MCP 工具，供外部 Agent 调用 |

## 2. UI 模块设计（AIDesignWindow）

### 2.1 菜单入口

- 在 `MainVSPScreen` 构造函数中新增：

```cpp
m_AIDesignMenuItem.Init( this, m_MenuBar, "AI辅助/AI 设计..." );
```

- `ActionCB` 中分发：

```cpp
else if ( data == &m_AIDesignMenuItem )
{
    AIDesignWindow::ShowWindow();
}
```

- 菜单项经过 R1 汉化框架的 `TrMenuPath`；未命中的新路径回退原文，因此显示为 **“AI辅助 → AI 设计...”**。
- 为便于自动化测试，支持环境变量 `OPENVSP_AI_AUTOSTART=1` 在启动 1.5 s 后自动打开 AI 面板（不影响正常使用）。

### 2.1.1 技术文档上传

- “设计需求”文本框下方新增 **[上传文档…]** / **[清空附件]**；
- 支持 `.docx`、`.pdf`、`.xlsx`、`.xls`、`.txt`、`.md`、`.csv`、`.json`、`.log`；
- C++ 只负责选择文件，将绝对路径数组写入 `ai_job.json` 的 `"attachments": [...]`；
- 解析在 Python 后端完成（`ai_design/attachments.py`）：提取正文/表格/工作表文本，单文件与总字符限幅；
- 文档内容与自然语言需求合并：离线模式并入规则解析，LLM 模式作为“技术数据（非指令）”注入 user 消息，模型抽取参数/设备选型/约束后调用 OpenVSP 工具；
- 旧版 `.doc` 提示用户另存为 `.docx`；扫描版 PDF 无 OCR，会提示无文本。

### 2.1.2 上传 .vsp3 案例

- “上传文档…”下方新增 **上传案例…**（BROWSE_FILE，仅 `.vsp3`）；
- C++ 写入 `ai_job.json` 的 `"case_model"`；GA 模式同时把案例作为 `seed_model`；
- 后端 `vsp_bridge.summarize_case_parameters()` 读取案例主翼/机身/尾翼摘要，
  `designer.apply_case_baseline()` 以案例为基线（prompt 显式参数可覆盖）；
- design 任务按自然语言修改意图（AR/面积/后掠/上反/机身加长等）重建模型；
  GA 任务以案例为优化基线（`baseline_source=case_model`）；
- 结果 `result.json` 记录 `case_model/based_on_case/case_parameters/case_applied`。

### 2.2 服务商与模型列表

内置预设（2026-11 调研结果，模型名动态获取优先）：

| 服务商 | base_url | 默认模型 | 内置回退清单 |
|---|---|---|---|
| DeepSeek | `https://api.deepseek.com` | `deepseek-flash` | deepseek-flash, deepseek-v4-pro |
| GLM（智谱） | `https://open.bigmodel.cn/api/paas/v4` | `glm-5.3` | glm-5.3, glm-5.3-flash, glm-5.3-flashx, glm-5.2 |
| Kimi（月之暗面） | `https://api.moonshot.cn/v1` | `kimi-k3.1-pro` | kimi-k3.1-pro, kimi-k3.1-pro-highspeed, kimi-k3, kimi-k2.7-code, kimi-k2.6 |
| GPT（OpenAI） | `https://api.openai.com/v1` | `gpt-6-astra` | gpt-6-astra, gpt-5.6-sol, gpt-5.6-terra, gpt-5.6-luna |
| 自定义 | 用户输入 | 用户输入/手填 | — |

- `[获取模型列表]` 通过 WinHTTP 请求 `{base}/models`，Bearer 鉴权，15 s 超时；
- 成功：解析 `data[].id` 填入下拉框（可编辑，支持手填）；
- 失败：**自动回退内置清单**，状态栏/日志说明原因（401/404/超时等），不阻塞用户。
- 模型名失效（如 DeepSeek 2026-07-24 停止 `deepseek-chat`、Kimi `moonshot-v1` 2026-08-31 下线）由“动态列表 + 内置回退”缓解。

### 2.3 API Key 安全

- UI 输入框为密码模式；
- 保存配置时使用 **Windows DPAPI**（`CryptProtectData`，当前用户、本机）加密为 base64，写入 `%LOCALAPPDATA%\OpenVSP-R2\ai_ui.cfg`；
- 启动子进程时通过 **仅子进程可见的环境变量** `OPENVSP_AI_API_KEY` 传递；
- 任务配置文件 `ai_job.json` 只写 `api_key_env`，**不落盘明文 Key**；
- 日志不打印 Key；错误信息只提示 HTTP 状态码。

### 2.3.1 多服务商 Key 持久化与验证

- Key 输入框右侧新增“保存”按钮；按服务商分别保存在 `%LOCALAPPDATA%\OpenVSP-R2\ai_ui.cfg`；
- 每条 Key 用 Windows DPAPI 加密（`api_key_<provider>=dpapi:<base64>`），配置中无明文；
- 切换服务商时自动载入对应 Key，并在后台异步调用该服务商的 `chat/completions` 做最小验证（`ping`，≤8 token），结果通过 `Fl::awake` 回主线程显示；
- 软件启动时恢复上次服务商/地址/模型/Key 并自动验证；
- Key 仅发往用户选择的服务商 HTTPS 端点，不进入 OpenVSP 日志、不上传第三方。

### 2.4 子进程与日志

- `CreateProcessW` 以隐藏窗口启动 `python ai_design_agent.py --config ai_job.json [--offline]`，工作目录为本次输出目录；
- 标准输出/错误重定向到匿名管道，后台 `std::thread` 按行读取，`Fl::awake` 投递到 UI 线程，追加到日志控件；
- 结束读取 `result.json`，成功则启用“打开设计报告”（`ShellExecuteW`）；
- `[停止]` 调用 `TerminateProcess`，并回收线程/句柄。

## 3. AI 后端接口契约

### 3.1 输入配置（ai_job.json）

```json
{
  "provider": "deepseek",
  "base_url": "https://api.deepseek.com",
  "api_key": "",
  "api_key_env": "OPENVSP_AI_API_KEY",
  "model": "deepseek-flash",
  "prompt": "设计一架最大起飞重量 200 kg、海拔 5000 m、速度 30~110 m/s 的大展弦比固定翼无人机……",
  "output_dir": "C:\\Users\\<user>\\Documents\\OpenVSP-R2\\designs\\20261101-130000",
  "report_template": "<安装目录>\\ai\\templates\\design_report_template.docx",
  "mode": "auto",
  "max_iterations": 4,
  "ui": "openvsp-r2"
}
```

### 3.2 输出 result.json

```json
{
  "ok": true,
  "report_path": "...\\设计报告.docx",
  "model_path": "...\\design.vsp3",
  "metrics": { "S_ref": 4.5, "AR": 13.5, "CL_alpha": 5.95, "L_D_max": 22.9 },
  "error": "",
  "log_tail": []
}
```

### 3.3 stdout 日志协议（UI 逐行展示）

| 前缀 | 含义 |
|---|---|
| `[status]` | 阶段状态（解析需求/建模/求解/报告完成） |
| `[plan]` | 模型规划摘要 |
| `[tool]` | 工具调用（名称、关键参数、耗时） |
| `[error]` | 可恢复/致命错误 |
| 其他 | 普通日志 |

离线模式（无 Key）不调用大模型，使用内置规则设计流程，仍生成模型、VSPAERO 结果与报告，便于演示/测试。

## 3.5 AI 结果回导 OpenVSP（导入OpenVSP）

- AI 面板完成后记录 `result.json` 的 `model_path`；
- 点击“导入OpenVSP”时调用 `AIDesignWindow` 中注册的导入回调
  （`MainVSPScreen::LoadModelForEditing`），走与 `File/Open...` 相同的
  `Vehicle::Renew()` → `SetVSP3FileName()` → `ReadXMLFile()` 流程，
  更新视图中心并重绘；
- 模型替换当前车辆后即可在 GUI 中编辑，不需要重新启动 OpenVSP；
- 未注册回调或没有可导入模型时给出明确提示。

## 4. MCP 服务器设计

- 传输：**stdio + 换行分隔 JSON-RPC 2.0**；
- 握手：legacy `initialize`（`protocolVersion` = `2025-11-25`）→ `notifications/initialized`；
- 能力：`capabilities.tools`；`tools/list`、`tools/call`、`ping`、`shutdown`；
- 工具名统一小写下划线，与 OpenAI/DeepSeek function name 兼容；
- 日志只写 stderr，stdout 仅协议 JSON；任何 `print` 均被重定向到 stderr；
- 长任务（VSPAERO）在工具内同步执行并返回摘要/文件路径，后续可扩展 `notifications/progress`。

工具清单：

| 工具 | 权限 | 说明 |
|---|---|---|
| `openvsp_status` | read | 版本、安装目录、Python API/VSPAERO 可用性 |
| `openvsp_new_model` | write | 新建空模型 |
| `openvsp_build_aircraft` | write | 按结构化 spec 生成机翼/机身/尾翼/操纵面 |
| `openvsp_get_geometry` | read | 列出部件、类型、关键参数 |
| `openvsp_run_vspaero` | run | 运行极曲线/稳定性/侧滑计算并解析结果 |
| `openvsp_export` | write | 导出 vsp3 / STL / CSV |
| `openvsp_generate_report` | write | 用内置模板生成 Word 报告 |
| `openvsp_list_files` | read | 列出工作目录文件 |

详细安装配置见 `docs/03-MCP服务器使用说明.md`。

## 5. 关键技术决策

1. **不修改 OpenVSP 几何/求解内核**：AI 模块只通过菜单 + 独立窗口 + 子进程接入，最大限度保持 R1 的几何与 VSPAERO 行为不变，降低回归风险。
2. **C++ 只做 UI 与模型列表**：大模型调用/工具循环放在 Python，便于跨 provider 适配与快速迭代；C++ 侧无需引入 JSON/HTTP 依赖库（WinHTTP 系统自带）。
3. **Key 不落盘、不进日志**：DPAPI + 子进程环境变量；配置只保存 provider/base/model。
4. **模型列表三级兜底**：内置清单 → `/models` 动态获取 → 手填模型 ID；智谱 `/models` 未文档化也能工作。
5. **MCP 先 legacy 后 modern**：存量 Claude Desktop/Cursor/DSH 多为 legacy 握手；2026-07-28 modern 协议作为后续 dual-era 扩展。
6. **离线模式**：无网络/无 Key 时仍可跑通“需求→模型→VSPAERO→报告”，便于验收与演示。

## 7. 已知限制

1. **Python 依赖**：AI 后端需要本机 **Python 3.13.x**（随包 OpenVSP Python API 为 cp313；依赖 numpy/python-docx/matplotlib，安装包提供 `setup_ai_env.bat`）。R2 便携包已包含 OpenVSP Python API（`python\openvsp`），但未内嵌 Python 运行时，后续可增加嵌入式 Python。
2. **VSPAERO 数值稳定性**：厚体机身 + 薄面翼面 + 操纵面切口的混合模型在部分几何下会出现非物理结果（NaN/正阻尼），AI 后端内置“全薄面 VLM”降级路径，并在报告/日志中注明。
3. **模型名快速迭代**：默认模型名会随厂商下线而变化，必须依赖动态 `/models` 或手填；GLM `/models` 待实测。
4. **MCP 仅 legacy 握手**：modern（2026-07-28）客户端需要后续 dual-era 适配。
5. **长任务取消**：UI 的“停止”会终止 Python 进程，可能留下 VSPAERO 子进程；后续增加进程树清理。
6. **未做代码签名**：与 R1 一致，安装包/可执行文件未签名。
