## 0. 结论摘要

1. **统一走 OpenAI 兼容协议，但不能只硬编码一个 base_url。** OpenAI、DeepSeek、Kimi 的模型列表端点有官方文档；智谱官方 API 文档只给了 `https://open.bigmodel.cn/api/paas/v4` 和 `chat/completions`，**没有 `GET /models` 的官方说明**；未带 Key 探测该路径返回 **401（认证错误）**，但鉴权可能先于路由，不能据此断定端点一定存在，带 Key 的响应结构待实测。仍必须做“内置清单 + 允许手填模型 ID + 运行时探测”的三级兜底。
2. **模型名变化很快，必须动态拉取。** 截至 2026-11-01：DeepSeek 官方当前模型是 `deepseek-flash`、`deepseek-v4-pro`；`deepseek-chat` / `deepseek-reasoner` 已按官方变更日志于 **2026-07-24 停止**。Kimi 的 `moonshot-v1` 系列已于 2026-08-31 下线；智谱当前为 GLM-5.3 / 5.3-Flash / 5.3-FlashX / 5.2；OpenAI 2026 年已发布 GPT-5.6（Sol/Terra/Luna）与 GPT-6 Astra。
3. **C++ FLTK 只负责“发现与展示”，Python 后端负责“对话与工具循环”。** C++ 用 WinHTTP 拉 `GET /models`、缓存、刷新、展示错误；Python 用 OpenAI SDK / httpx 执行 `chat/completions`、解析 `tool_calls`、校验 JSON Schema、调用 OpenVSP Python API，并承载 MCP 服务器。这样既不让 FLTK 承担复杂的工具编排，也避免 Python 启动慢影响设置界面。
4. **MCP 存在“两代协议”差异。** 当前规范是 **2026-07-28**（modern：不再用 `initialize` 握手，改为每个请求在 `_meta` 带版本）；**2025-11-25 及更早**是 legacy：`initialize` → `initialized` 通知。不少存量客户端与教程仍按 legacy 握手实现。R2 的 MCP 服务器建议 **先实现 legacy 握手（推荐 `2025-06-18` 或 `2025-11-25`），再补 modern 的 dual-era 兼容**，否则 Claude Desktop / Cursor / 部分 DSH 版本可能连不上。
5. **密钥首选 Windows 凭据管理器**（`CredWriteW` / `CredReadW`，底层由 DPAPI 按用户保护）；环境变量只作开发和 CI 兜底；配置文件绝不保存明文 Key；日志必须脱敏 `Authorization`、`api_key`、`sk-`、`Bearer`。
6. **桌面端没有浏览器 CORS 问题**，因为 WinHTTP / Python 直连不经过浏览器；只有“WebView 前端调本地 HTTP 服务”或“MCP Streamable HTTP 暴露给浏览器”时才需要处理 Origin/CORS。MCP 的 HTTP 传输本身要求校验 `Origin`，并建议只绑定 `127.0.0.1`。

## 1. OpenAI 兼容 API 基线

### 1.1 通用约定

- 传输：HTTPS + JSON。
- 鉴权：`Authorization: Bearer <API_KEY>`，不要放在 URL query 里。
- 请求头：`Content-Type: application/json`，模型列表可加 `Accept: application/json`。
- 端点拼接：`{base_url}/models`、`{base_url}/chat/completions`。**base_url 是否含 `/v1` 各家不同**（见下表），拼错会得到 404。
- 错误响应通常是 `{"error":{"message":"...","type":"...","code":"..."}}`，但各家的字段和 HTTP 状态码不完全一致，客户端要容错。

| 供应商 | base_url | 模型列表 | 对话补全 | 备注 |
|---|---|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `GET /v1/models` | `POST /v1/chat/completions` | 官方参考：[O1][O2] |
| DeepSeek | `https://api.deepseek.com` | `GET /models` | `POST /chat/completions` | 官方示例 base_url **不带** `/v1`；SDK 会拼 `/chat/completions`。[D1][D2] |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | **官方未文档化**；探测未带 Key 返回 401（结构待实测） | `POST /chat/completions` | 官方 API 通用端点。[Z2] |
| Kimi | `https://api.moonshot.cn/v1` | `GET /v1/models` | `POST /v1/chat/completions` | base_url 含 `/v1`。[K1][K2] |

> **实现建议**：把 `base_url` 与 `endpoint_template` 分开存。不要对用户输入简单执行 `base_url + "/v1"`；应当让每个 provider 预设一个“拼接规则”，并允许高级用户直接填完整 URL。

### 1.2 GET /v1/models

请求示例（OpenAI）：

```http
GET /v1/models HTTP/1.1
Host: api.openai.com
Authorization: Bearer $OPENAI_API_KEY
Accept: application/json
```

响应结构（OpenAI 及多数兼容实现）：

```json
{
  "object": "list",
  "data": [
    {
      "id": "gpt-6-astra",
      "object": "model",
      "created": 1780000000,
      "owned_by": "openai"
    }
  ]
}
```

> 上例中的 `gpt-6-astra` 仅为占位示例，实际可用 ID 以 `GET /v1/models` 返回为准（OpenAI 模型 ID 待实测）。

DeepSeek / Kimi 会在 `data[]` 里增加元数据，例如：

- DeepSeek：`name`、`context_window`、`max_output_tokens`、`input_modalities`、`output_modalities`、`effort.supported_levels`、`api_capabilities` 等。[D2]
- Kimi：`context_length`、`supports_image_in`、`supports_video_in`、`supports_reasoning` 等。[K2]

> 客户端只应依赖 `data[].id` 作为模型标识；其他字段用于展示和能力提示，缺失时不要报错。

三家可直接验证的 curl：

```bash
# OpenAI
curl -sS https://api.openai.com/v1/models \
  -H "Authorization: Bearer $OPENAI_API_KEY"

# DeepSeek（官方 base_url 不带 /v1）
curl -sS https://api.deepseek.com/models \
  -H "Authorization: Bearer $DEEPSEEK_API_KEY"

# Kimi
curl -sS https://api.moonshot.cn/v1/models \
  -H "Authorization: Bearer $MOONSHOT_API_KEY"
```

> 智谱：官方文档没有给出 `GET /models`。实测未带 Key 请求 `GET https://open.bigmodel.cn/api/paas/v4/models` 返回 **401**（`{"error":{"code":"1001","message":"Header中未收到Authorization参数..."}}`），说明服务可达且鉴权前置，但不能据此断定该路径一定存在；带 Key 的响应字段与模型列表仍**待实测**。仍要按“未文档化”处理：失败时回退到内置模型清单，不要把 401/404 当成致命错误。

### 1.3 POST /v1/chat/completions

最小请求（不带工具）：

```json
{
  "model": "deepseek-flash",
  "messages": [
    {"role": "system", "content": "你是 OpenVSP 的气动设计助手。"},
    {"role": "user", "content": "把机翼展长改为 10.5 米，并解释对升阻比的影响。"}
  ],
  "temperature": 0.2,
  "max_tokens": 2048,
  "stream": false
}
```

带工具调用的请求：

```json
{
  "model": "deepseek-flash",
  "messages": [
    {"role": "system", "content": "只调用已提供的工具；修改几何前先说明意图。"},
    {"role": "user", "content": "把机翼展长改为 10.5 米。"}

  "tools": [
    {
      "type": "function",

          "type": "object",
          "properties": {
            "changes": {
              "type": "array",
              "items": {
                "type": "object",
                "properties": {
                  "parm_id": {"type": "string"},

                },
                "required": ["parm_id", "value"],

          "required": ["changes"],
          "additionalProperties": false
        }
      }

  "tool_choice": "auto",

}
```

模型决定调用工具时的响应：

```json
{
  "id": "chatcmpl-abc123",
  "object": "chat.completion",
  "created": 1780000000,
  "model": "deepseek-flash",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": null,
        "tool_calls": [
          {
            "id": "call_001",
            "type": "function",
            "function": {
              "name": "openvsp_set_parameters",
              "arguments": "{\"changes\":[{\"parm_id\":\"Wing_Geom_1_Chord\",\"value\":10.5}]}"
            }
          }
        ]
      },
      "finish_reason": "tool_calls"
    }
  ],
  "usage": {
    "prompt_tokens": 812,
    "completion_tokens": 46,
    "total_tokens": 858
  }
}
```

客户端执行完工具后，把 **assistant 消息原样**（含 `tool_calls`）追加进历史，再追加 `role: "tool"` 的结果：

```json
{
  "role": "tool",
  "tool_call_id": "call_001",
  "content": "{\"ok\":true,\"updated\":[{\"parm_id\":\"Wing_Geom_1_Chord\",\"value\":10.5}]}"
}
```

然后再次请求 `chat/completions`，直到模型返回普通文本、`finish_reason` 为 `stop` 或达到最大轮数。

关键点：

- `function.arguments` 是 **JSON 字符串**，不是对象；模型可能生成非法 JSON，必须 `json.loads` 后按 Schema 校验。[D3][D4]
- `tool_call_id` 必须与 assistant 消息里的 `id` 对应，否则 400。
- `tool_calls` 可能一次返回多个（并行工具调用）；要逐个执行并逐个回填 `role: tool`。
- `finish_reason` 可能是 `stop`、`length`、`tool_calls`、`content_filter` 等；不要只判断 `content` 是否为空。
- 流式模式下 `tool_calls` 会以增量片段返回，需要按 `index` 聚合 `id`、`function.name`、`function.arguments` 后再执行。

### 1.4 工具循环的推荐实现（Python）

```python
import json
from openai import OpenAI

MAX_ROUNDS = 8
client = OpenAI(base_url=BASE_URL, api_key=API_KEY, timeout=120.0)

def run_tool_loop(messages, tools, dispatch):
    for _ in range(MAX_ROUNDS):
        resp = client.chat.completions.create(
            model=MODEL,
            messages=messages,
            tools=tools,
            tool_choice="auto",
            temperature=0.2,
            max_tokens=4096,
        )
        choice = resp.choices[0]
        msg = choice.message

        if not msg.tool_calls:
            return msg.content or ""

        # 必须保留 tool_calls 字段
        messages.append(msg.model_dump(exclude_none=True))

        for tc in msg.tool_calls:
            name = tc.function.name
            try:
                args = json.loads(tc.function.arguments or "{}")
                result = dispatch(name, args)          # 内部做 Schema 校验、权限检查、超时
                content = json.dumps(result, ensure_ascii=False)
            except Exception as e:
                content = json.dumps(
                    {"ok": False, "error": f"{type(e).__name__}: {e}"},
                    ensure_ascii=False,
                )
            messages.append({
                "role": "tool",
                "tool_call_id": tc.id,
                "content": content,
            })

    return "已达到最大工具调用轮数，请缩小任务范围后重试。"
```

补充要求：

- **每个工具单独超时**；VSPAERO 这类长任务要有进度和取消，不能用一个 120 秒的 HTTP 超时硬扛。
- **工具结果限长**；超过阈值时截断并提示模型，不要直接把几 MB 的网格/结果塞回对话。
- **未知工具/非法参数**不要抛给用户，而是作为 `role: tool` 的错误结果回填，让模型自我修正。
- **写操作**（改几何、保存、导出、运行求解）必须经过 UI 确认，不能只靠模型判断。

### 1.5 Bearer 鉴权与错误处理

- 令牌只放 `Authorization` 头；不要拼进 URL、不要写进异常消息。
- 常见状态码：

| 状态码 | 含义 | 处理 |
|---|---|---|
| 400 | 请求体/工具 Schema 不合法 | 记录脱敏后的响应体，提示模型或用户修正 |
| 401 | Key 无效/过期 | 提示重新输入，不要自动重试 |
| 403 | 无权限、地区/模型未开通 | 展示官方错误信息，检查套餐/Key 类型 |
| 404 | 模型名或路径错误 | 刷新模型列表；检查 base_url 是否重复 `/v1` |
| 429 | 限流/配额 | 指数退避 + 抖动；尊重 `Retry-After` |
| 5xx | 上游故障 | 有限重试（2~3 次），区分超时与业务错误 |

## 2. 各供应商核对

### 2.1 DeepSeek

**官方入口**：[D1] `https://api-docs.deepseek.com/`

| 项目 | 核对结果 |
|---|---|
| base_url（OpenAI 格式） | `https://api.deepseek.com` |
| base_url（Anthropic 格式） | `https://api.deepseek.com/anthropic` |
| 模型列表 | `GET https://api.deepseek.com/models` |
| 对话补全 | `POST https://api.deepseek.com/chat/completions` |
| 鉴权 | `Authorization: Bearer <DEEPSEEK_API_KEY>` |
| 当前模型 | `deepseek-flash`、`deepseek-v4-pro`（2026-10-17 文档） |
| 旧模型名 | `deepseek-chat` / `deepseek-reasoner` **已于 2026-07-24 停止**（官方 changelog）[D5] |

**重要更正**：任务描述里的 `deepseek-chat` / `deepseek-reasoner` 是 2025 年的旧名，不是 2026-11 的当前模型名。官方 2026-04-24 的变更日志明确写道：两个旧名将在三个月后（2026-07-24）停止；期间分别指向 `deepseek-v4-flash` 的非思考/思考模式。2026-09-10 起官方模型名改为 `deepseek-flash`，旧名 `deepseek-v4-flash` 等仅作临时兼容。**R2 不要再把旧名作为默认值**；如果用户手填旧名，按“可能 400”处理并提示。

**工具调用要点**（官方 `Tool Calls` 与 Chat Completions 参考）：

- 请求：`tools: [{type:"function", function:{name, description, parameters, strict?}}]`。
- `tool_choice`：`none` / `auto` / `required` / 指定函数；**thinking 模式下不支持 `required` 和指定函数**，会返回 400。[D3]
- `strict` 模式是 Beta：必须使用 `base_url="https://api.deepseek.com/beta"`，并且所有 object 属性都要 `required`、`additionalProperties: false`。[D4]
- 响应：`choices[0].message.tool_calls[]`，其中 `function.arguments` 是字符串；官方明确提醒“模型不总是生成合法 JSON，可能臆造参数”，必须校验。
- `finish_reason` 可能为 `tool_calls`；流式时 `usage` 只在最后一块（或 `stream_options.include_usage`）出现。
- 思考模式：`thinking: {"type":"enabled"|"disabled"}`；`reasoning_effort`: `none|low|high|max`（`minimal` 映射为 `low`，`medium/xhigh` 映射为 `high`）。

**模型列表响应**：除 `id/object/owned_by` 外，还包含 `context_window`、`max_output_tokens`、`input_modalities`、`output_modalities`、`effort`、`api_capabilities` 等。R2 可以只展示 `id`、`context_window`、`max_output_tokens`，其余忽略。

**计费提示**：DeepSeek 采用峰谷价，缓存命中/未命中不同价；工具循环会反复发送历史，缓存命中率对成本影响很大。[D6]

### 2.2 智谱 GLM

**官方入口**：[Z1] `https://docs.bigmodel.cn/cn/guide/develop/openai/introduction`、[Z2] `https://docs.bigmodel.cn/cn/api/introduction`

| 项目 | 核对结果 |
|---|---|
| base_url | `https://open.bigmodel.cn/api/paas/v4`（官方 API 通用端点） |
| 对话补全 | `POST /chat/completions` |
| 模型列表 | **官方 API 文档未列出 `GET /models`**；未带 Key 探测返回 401（鉴权前置，结构待实测） |
| 鉴权 | `Authorization: Bearer <API_KEY>` |
| 当前模型 | `glm-5.3`、`glm-5.3-flash`、`glm-5.3-flashx`、`glm-5.2`（模型概览；API ID 以控制台为准）[Z3] |
| 旧模型 | GLM-4.x 系列仍可能存在，但以控制台/模型页为准 |

**模型列表的结论**：官方 OpenAI 兼容页只演示了 `client.chat.completions.create(...)`，API 快速开始也只列 `chat/completions`；没有 `GET /models` 的请求/响应说明。因此：

- R2 对智谱**默认使用内置模型清单**：`glm-5.3`、`glm-5.3-flash`、`glm-5.3-flashx`、`glm-5.2`（ID 以控制台为准），并允许用户手填模型 ID。
- “刷新模型”可以对 `https://open.bigmodel.cn/api/paas/v4/models` 做一次**探测**：未带 Key 已返回 401，说明服务可达且鉴权前置；带 Key 成功后合并列表，失败则静默回退，不要把这个探测失败展示成“网络错误”。
- 该端点的带 Key 响应结构标记 **待实测**，不要在文档/UI 中宣称“智谱官方支持 /models”。

**工具调用要点**（官方“工具调用”页）：

- 请求：`tools` + `tool_choice`；**`tool_choice` 默认且仅支持 `auto`**（官方原文），不要向智谱发送 `required` 或指定函数，否则可能 400/被忽略。
- 响应：`message.tool_calls[]`，含 `id`、`function.name`、`function.arguments`（JSON 字符串）。
- 回填：`{"role":"tool","content":"...","tool_call_id":tool_call.id}`。
- 思考模式：通过 `extra_body={"thinking":{"type":"enabled"}}` 开启；流式响应里读 `delta.reasoning_content` 与 `delta.content`。
- 参数差异：`temperature` 区间是 `(0,1)`，官方明确 `do_sample=False`（temperature=0）在 OpenAI 调用中不适用；这与 OpenAI 的 `[0,2]` 不同，UI 要做 provider 级约束。
- **Coding Plan 是独立端点、独立 Key**，不能和标准 API Key 混用；R2 如果只做标准 API，要在错误提示里说明。

## 3. MCP（Model Context Protocol）

### 3.1 传输与 JSON-RPC 2.0

MCP 用 **JSON-RPC 2.0** 编码消息，UTF-8。标准传输有两种：

1. **stdio**：客户端把 MCP 服务器作为子进程启动，服务器从 `stdin` 读、向 `stdout` 写；消息以**换行分隔**，且单条消息**不得包含内嵌换行**；日志只能写 `stderr`，`stdout` 必须是合法 MCP 消息。[M2]
2. **Streamable HTTP**：POST/GET 一个 MCP endpoint，可用 SSE；要求校验 `Origin`、实现认证，并建议本地只绑定 `127.0.0.1`。[M2]

对 R2 的 MCP 服务器，**首选 stdio**：不需要端口、不受防火墙影响、生命周期跟客户端走；代价是 C++/Python 侧要严格管理子进程和 stdout。

最小消息：

```json
{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}
```

```json
{"jsonrpc":"2.0","id":1,"result":{"tools":[]}}
```

错误：

```json
{"jsonrpc":"2.0","id":1,"error":{"code":-32602,"message":"Unknown tool: foo"}}
```

常用错误码：`-32700` 解析错误、`-32600` 非法请求、`-32601` 方法不存在、`-32602` 参数非法、`-32603` 内部错误。

### 3.2 协议版本：legacy 与 modern

这是 R2 最容易踩坑的地方。

| 版本 | 状态 | 握手方式 |
|---|---|---|
| **2026-07-28** | 当前（current） | **没有 `initialize` 握手**；每个请求在 `_meta` 里带 `io.modelcontextprotocol/protocolVersion`、`clientInfo`、`clientCapabilities`；服务器必须实现 `server/discover`。[M1] |
| **2025-11-25** | legacy | `initialize` 请求 → 响应 → `notifications/initialized` |
| **2025-06-18** | legacy | 同上，字段略少 |

官方版本页明确：`2026-07-28` 及以后是 “modern”，`2025-11-25` 及更早是 “legacy”；两者可以双栈（dual-era）。legacy 客户端连 modern 服务器会失败，modern 客户端连 legacy 服务器也失败（除非 dual-era）。[M1]

**R2 建议**：

- **第一版按 legacy 实现**，`protocolVersion` 用 `2025-06-18` 或 `2025-11-25`。Claude Desktop / Cursor / DSH 的不少存量配置和教程基于 `initialize` 流程，兼容性最好。
- 在 `initialize` 响应里返回客户端请求的版本（如果支持），否则返回服务器支持的最新版本；客户端不支持就断开。
- 第二版再加 modern：`server/discover` + `_meta`，并保留 legacy 分支，形成 dual-era。
- 不要只实现 modern 就宣称“支持 MCP”；部分客户端会直接发 `initialize`。

### 3.3 legacy 初始化（initialize）

请求：

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "protocolVersion": "2025-06-18",
    "capabilities": {
      "roots": {"listChanged": true},
      "sampling": {},
      "elicitation": {}
    },
    "clientInfo": {
      "name": "OpenVSP-R2",
      "title": "OpenVSP R2",
      "version": "0.1.0"
    }
  }
}
```

响应：

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "protocolVersion": "2025-06-18",
    "capabilities": {
      "tools": {"listChanged": true}
    },
    "serverInfo": {
      "name": "openvsp-r2",
      "title": "OpenVSP R2 MCP Server",
      "version": "0.1.0"
    },
    "instructions": "OpenVSP R2 几何与气动分析工具。写操作需要用户确认。"
  }
}
```

随后客户端必须发送：

```json
{"jsonrpc":"2.0","method":"notifications/initialized"}
```

要点：

- `initialize` 必须是第一条交互；服务器在收到 `initialized` 前不应主动发请求（ping/logging 除外）。[M4]
- `capabilities.tools.listChanged` 表示工具列表可能变化；如果不变，可以设为 `false` 或省略。
- `serverInfo` 的 `name` 不保证全局唯一，客户端做多服务器聚合时要用自己的前缀策略。
- 2025-11-25 还增加了 `title`、`description`、`icons`、`websiteUrl`、`tasks` 等可选字段；不填不影响旧客户端。

### 3.4 tools/list 与 tools/call

**tools/list 请求**：

```json
{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{"cursor":"optional"}}
```

**响应**（legacy）：

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "tools": [
      {
        "name": "openvsp_list_components",
        "title": "列出部件",
        "description": "列出当前模型中的几何部件及其类型。",
        "inputSchema": {
          "type": "object",
          "properties": {},
          "additionalProperties": false
        }
      }
    ]
  }
}
```

**tools/call 请求**：

```json
{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "openvsp_list_components",
    "arguments": {}
  }
}
```

**响应**：

```json
{
  "jsonrpc": "2.0",
  "id": 3,
  "result": {
    "content": [
      {"type": "text", "text": "Wing, Fuselage, Tail"}
    ],
    "isError": false
  }
}
```

要点：

- `tools/list` 的 `inputSchema` 必须是合法 JSON Schema；无参数工具建议用 `{"type":"object","additionalProperties":false}`。[M3]
- `tools/call` 的参数在 `params.arguments`；结果在 `result.content[]`，每个元素有 `type`（`text`/`image`/`audio`/`resource_link`/`resource`）。
- **协议错误**（未知工具、参数不合法）返回 JSON-RPC `error`；**工具执行错误**返回 `result.isError: true` + 文本内容，让模型能自我修正。[M3]
- 可选 `structuredContent` 返回结构化结果；如果提供 `outputSchema`，服务器返回的结构必须符合它。
- 长任务可以发 `notifications/progress`；客户端取消用 `notifications/cancelled`（带上被取消请求的 `id`）。
- 工具名建议只用小写字母、数字、下划线；MCP 允许点号，但 OpenAI 函数名不允许点号，跨协议时要映射（见 4.4）。

### 3.6 MCP 服务器实现清单（Python）

- 入口：`python -m openvsp_r2.mcp_server`；stdout 只写协议消息，日志全部 `stderr`。
- 启动即设置 UTF-8、无 BOM、LF 换行：

```python
import sys
sys.stdin.reconfigure(encoding="utf-8")
sys.stdout.reconfigure(encoding="utf-8", newline="\n")
sys.stderr.reconfigure(encoding="utf-8", newline="\n")
```

- 逐行读 `stdin`，`json.loads`；每条消息处理完立即 `print(json.dumps(resp, ensure_ascii=False), flush=True)`。
- 至少实现：`initialize`、`notifications/initialized`、`tools/list`、`tools/call`；建议实现 `ping` 与 `notifications/cancelled`。
- 工具执行放在线程池/子进程，避免阻塞读循环；长任务发 progress；超时返回 `isError: true`。
- 退出：监听 `stdin` EOF，清理 OpenVSP 子进程/临时文件；Windows 下用 Job Object 保证子进程随父进程退出。
- 安全：工具白名单、路径白名单（禁止 `..` 和任意绝对路径）、禁用 `shell=True`、写操作要求 `confirm: true` 或 GUI 弹窗确认。

## 4. OpenVSP R2 选型建议

### 4.1 职责边界

| 层 | 组件/语言 | 应负责 | 不应负责 |
|---|---|---|---|
| UI 层 | C++ / FLTK | 供应商预设、base_url、密钥输入（密码框）、模型下拉/刷新、对话展示、工具调用轨迹、确认对话框、取消、错误中文化、日志脱敏 | 不执行工具循环；不把密钥写入日志/命令行；不直接编辑 OpenVSP 模型 |
| 模型发现 | C++ / WinHTTP | `GET /models`、代理/TLS、超时、缓存、离线兜底、状态展示 | 不解析复杂业务 JSON；不调用 chat |
| AI 后端 | Python | `chat/completions`、流式解析、`tool_calls` 聚合、JSON Schema 校验、工具调度、重试/限流、token 统计 | 不做 UI；不信任模型参数；不绕过权限检查 |
| 工具执行 | Python + OpenVSP Python API | 读写参数、运行 VSPAERO、导出、结果解析 | 不直接对外暴露任意命令；不跳过确认 |
| MCP 服务器 | Python（stdio） | 协议握手、`tools/list`、`tools/call`、资源/提示、把调用转发给工具执行层 | 不自己实现一套几何逻辑；不向 stdout 打印日志 |

**为什么模型列表放 C++**：

- 设置界面要在 Python 后端启动前就能用；用户先选供应商、拉模型，再启动对话。
- WinHTTP 直接使用 Windows 系统代理和证书链，和 FLTK 原生应用一致；不需要把 Python 运行时作为 UI 的前置条件。
- 但 **C++ 只做 GET**：不实现 chat 的 SSE、工具循环、Schema 校验，避免重复造轮子。

**为什么工具循环放 Python**：

- OpenAI SDK 已处理重试、流式、`tool_calls` 解析；手写 C++ 成本高。
- JSON Schema 校验、MCP 客户端/服务器、OpenVSP Python API 都在 Python 生态。
- 便于写单元测试和 mock，不依赖 GUI。

**边界契约**：C++ → Python 只传 `{provider, base_url, model, messages, tool_policy, request_id}`；Python → C++ 以事件流返回 `{type: "delta"|"tool_call"|"tool_result"|"usage"|"error"|"done", ...}`。密钥不在这条消息里传递（见 4.5）。

### 4.2 C++ / WinHTTP 拉取模型列表

推荐流程：

1. 读取 provider 配置（base_url、endpoint 规则、超时、代理模式）。
2. `WinHttpOpen(L"OpenVSP-R2/0.1", WINHTTP_ACCESS_TYPE_AUTOMATIC_PROXY, ...)`；Windows 8.1+ 用自动代理，旧系统回退 `WINHTTP_ACCESS_TYPE_DEFAULT_PROXY`。[W2]
3. `WinHttpConnect(host, port)`；`WinHttpOpenRequest(..., L"GET", path, ..., WINHTTP_FLAG_SECURE)`。
4. 加头：`Authorization: Bearer <key>`、`Accept: application/json`；`WinHttpSendRequest` → `WinHttpReceiveResponse`。
5. 循环 `WinHttpQueryDataAvailable` + `WinHttpReadData` 读 body；限制最大 2 MB，防止异常响应撑爆内存。[W1]
6. `WinHttpSetTimeouts(5000, 10000, 10000, 20000)`：解析 5s、连接 10s、发送 10s、接收 20s。[W3]
7. 解析 `data[].id`；成功后写缓存 `%LOCALAPPDATA%\OpenVSP-R2\models\<provider>.json`，带 `fetched_at`、`base_url`、`etag`（如果有）。
8. UI 更新必须在主线程：工作线程 `Fl::awake(...)`，不要直接碰 FLTK 控件。
9. 失败：401/403/404/429/超时/TLS 分别给中文提示；展示“使用内置清单”按钮，不阻塞用户。

实现细节：

- **单飞**：同一 provider 同时只允许一个刷新请求；重复点击复用进行中的 future。
- **取消**：关闭 `HINTERNET` 句柄即可中断；线程退出前 `WinHttpCloseHandle` 全部句柄。
- **代理**：默认“系统代理”；高级设置允许“直连/自定义 host:port/绕过列表”。Python 侧必须使用同一套设置，否则会出现“C++ 能拉列表、Python 连不上”的诡异问题。
- **TLS**：WinHTTP 用 Schannel + 系统证书库；企业 MITM 根证书需安装到系统。**不要提供“忽略证书错误”作为默认选项**；最多作为高级开关并明确警告。
- **JSON**：复用 OpenVSP 现有 JSON 库；若没有合适的，引入单头 `nlohmann/json` 比手写解析安全。
- **缓存策略**：启动时先展示缓存，再后台刷新；缓存 TTL 建议 24h；base_url 或 Key 变化时缓存失效。

### 4.3 Python 工具循环

已在 1.4 给出骨架，这里补充工程约束：

- **模型无关**：`tools` 定义只写一次，四家共用；provider 差异放在“请求参数适配层”（例如智谱 `tool_choice` 只能 `auto`、DeepSeek thinking 下不能 `required`）。
- **Schema 校验**：用 `jsonschema` 对 `arguments` 做校验；不合法时回填错误，不要执行。
- **权限**：工具分级 `read` / `write` / `run` / `dangerous`；`write` 以上需要 GUI 确认；MCP 外部客户端调用时，确认可以落在客户端，但 GUI 要显示审计记录。
- **超时**：HTTP 连接 10s、普通对话 120s、流式空闲 60s；工具执行单独计时（VSPAERO 可能数分钟到数十分钟），不要用 HTTP 超时覆盖工具超时。
- **重试**：只对 429/5xx/网络错误重试；400/401/403 不重试；工具调用已经产生副作用时不要盲目重放。
- **成本**：累计 `usage`，在 UI 显示本轮/会话 token；设置 `max_tokens`、最大轮数、会话预算。
- **取消**：用户点“停止”时，取消 HTTP 流 + 终止工具子进程 + 回填 `cancelled` 事件；不要留下孤儿 VSPAERO 进程。

### 4.4 C++ 与 Python 的 IPC，以及“操作当前模型”的问题

**IPC 方案对比**：

| 方案 | 优点 | 缺点 | 建议 |
|---|---|---|---|
| stdio + NDJSON | 无端口、无防火墙、易清理；和 MCP 同构 | C++ 要管子进程、解析流、处理背压 | **推荐** |
| 127.0.0.1 HTTP + 随机端口 + 会话 token | 调试方便、可用 SSE | 端口/防火墙、需要鉴权、可能被本机其他进程访问 | 备选（WebView UI 时） |
| 命名管道 | Windows 原生、权限可控 | 跨平台差、实现复杂 | 可选 |

不推荐：把 API Key 放在命令行参数（进程列表可见）、把 Python 后端暴露到 `0.0.0.0`、无鉴权的 localhost 端口。

**关键问题：MCP 服务器如何操作“当前正在运行的 OpenVSP 模型”？**

MCP 客户端（Claude Desktop/Cursor/DSH）启动的是**独立进程**，它不能直接访问 FLTK 进程的内存。三种模式：

1. **文件模式（最简单）**：MCP 服务器用 OpenVSP Python API 打开 `.vsp3` 文件、修改、保存。适合批处理/无人值守；缺点是不能实时反映 GUI 里未保存的修改，且可能与 GUI 同时写同一文件。
2. **桥接模式（推荐）**：OpenVSP R2 内置一个“工具执行宿主”（C++ 或 Python sidecar），监听命名管道/loopback；MCP 服务器作为薄适配层，把 `tools/call` 转发给宿主，由宿主在 GUI 进程内执行。这样能操作当前模型、复用撤销栈、弹出确认框。
3. **无 GUI 模式**：MCP 服务器每次启动 headless OpenVSP 实例，适合服务器/CI；R2 桌面版可作为降级路径。

建议：**桥接模式为主，文件模式为降级**；MCP 服务器启动时先探测宿主是否在运行，不在则返回明确错误或进入文件模式。不要让两个进程同时写同一个 `.vsp3`；加文件锁/版本号，保存前提示“磁盘文件已被其他进程修改”。

**工具名映射**：MCP 允许工具名含点号（如 `openvsp.model.list`），但 OpenAI/DeepSeek 的函数名只允许字母、数字、下划线、短横线，且不超过 128 字符。**统一用下划线命名**（`openvsp_list_components`），既满足 MCP，也满足 LLM 工具调用；如果 MCP 侧必须用点号，做一层双向映射。

### 4.5 API Key 安全存储

**推荐优先级**：

1. **Windows 凭据管理器（首选）**：`CredWriteW` 写入 `CRED_TYPE_GENERIC`，`TargetName` 用 `OpenVSP-R2/<provider>`，`Persist` 用 `CRED_PERSIST_LOCAL_MACHINE`；运行时 `CredReadW` 读取。凭据由 DPAPI 按当前用户加密，其他用户不可读。[W4]
2. **DPAPI 加密文件（备选）**：`CryptProtectData` 加密后存 `%LOCALAPPDATA%\OpenVSP-R2\secrets\<provider>.bin`，带固定 entropy，`CRYPTPROTECT_UI_FORBIDDEN`；换机器/换用户无法解密。[W5]
3. **环境变量（开发/CI）**：`OPENAI_API_KEY`、`DEEPSEEK_API_KEY`、`ZAI_API_KEY`、`MOONSHOT_API_KEY`。只读不写；同用户的其他进程可读，不适合共享电脑。
4. **明文配置文件（禁止）**：包括 `settings.json`、`.env`、MCP 的 `env` 字段、日志。

**实现约定**：

- 配置文件只存 `provider`、`base_url`、`model`、`timeout`、`proxy`、`max_rounds`；**不存 Key**。
- C++ 读取凭据后，只在内存中保留到请求结束；不要复制到日志、异常、崩溃转储。
- Python 不通过命令行接收 Key；由 C++ 通过继承的环境变量（仅子进程）或 Python 自己读凭据管理器。更稳妥：**Python 自己读 Windows 凭据管理器**，C++ 只告诉它 provider 名。
- MCP 配置：Claude/Cursor 的 `env` 是明文，优先让服务器读凭据管理器；DSH 的 `config.env` 同样落盘，不要提交到仓库。
- 日志脱敏：统一封装 `redact()`，过滤 `Authorization`、`api_key`、`token`、`sk-`、`Bearer`；HTTP 客户端库的 DEBUG 日志在 release 关闭（`httpx`、`openai`、`urllib3`）。
- 崩溃转储：默认不生成完整堆转储；如必须生成，避免包含请求头和 Key 的内存页。
- UI：密码框、显示/隐藏、清除、测试连接；测试连接优先打 `/models`，智谱等列表端点未文档化时回退一次最小 `chat/completions` 请求；不打印 Key，错误信息不回显完整 Key（最多显示后 4 位）。

### 4.6 UI/UX 建议

- 供应商下拉：OpenAI / DeepSeek / 智谱 GLM / Kimi / 自定义（OpenAI 兼容）。
- 每个供应商预设 base_url、模型清单、默认模型、参数限制（如智谱 temperature 0~1、tool_choice 仅 auto）。
- “刷新模型”按钮：显示加载态、最后刷新时间、数据来源（官方/缓存/内置）；失败不阻塞。
- 模型下拉允许“手动输入 ID”，因为模型列表可能缺失（尤其智谱）或账号有灰度模型。
- 对话区显示：助手文本、工具调用卡片（工具名、参数、结果摘要、耗时、token）、确认按钮、取消按钮。
- 错误中文化：401 “Key 无效或过期”、403 “无权限/未开通”、404 “模型或路径不存在”、429 “限流，请稍后”、TLS “证书校验失败，请检查代理/根证书”。
- 成本提示：本轮 token、会话累计 token、预估费用（按 provider 价格表，可配置；价格会变，不要硬编码在代码里）。
- 安全提示：首次写操作前弹窗说明“AI 将修改当前模型”；提供“只读模式”开关。

| 9 | **MCP 版本分裂**：2026-07-28 modern 无 initialize；存量客户端多为 legacy | 客户端连不上、工具不出现 | 先 legacy（2025-06-18/2025-11-25），再 dual-era；用三家客户端回归 | 需实测 |
| 10 | **MCP stdio 污染**：任何 `print()`/库日志写 stdout 都会破坏协议 | 客户端解析失败、连接断开 | stdout 只写协议；日志强制 stderr；子进程捕获输出；启动时重定向 | 必须 |
| 11 | **安全**：提示注入（模型/文件名/工具结果）、任意路径、命令执行、密钥泄漏 | 数据泄露/模型被破坏 | 工具白名单、路径校验、禁用 shell、人工确认、日志脱敏、最小权限 Key | 必须 |
| 12 | **中文/编码**：Windows 代码页、中文路径、UTF-8 BOM | JSON 解析失败、乱码 | 全链路 UTF-8；`ensure_ascii=False`；`newline="\n"`；测试中文用户名/路径 | 需测试 |
| 13 | **OpenAI 文档访问受限**：官方站 403，模型 ID 无法逐字段核对 | 默认模型可能过时 | 以 `/v1/models` 为准；内置清单标注抓取日期；允许手填；上线前实测 | 待实测 |
| 14 | **限流/配额/地区**：429、403、余额不足 | 对话中断 | 退避重试；显示官方错误；预算/配额提示 | 需实测 |
| 15 | **MCP 工具 Schema 过大**：工具多、描述长，占用上下文 | 成本高、模型选错工具 | 工具分组/按需加载；描述精简；`tools/list` 分页/缓存；只暴露当前任务需要的工具 | 设计优化 |
