# OpenVSP R2 可靠设计软件优化方案

**文档编号：** OVSP-RD-OPT-001  
**版本：** 1.0  
**日期：** 2026-11-02  
**状态：** 建议稿，待产品、工程、验证负责人评审  
**输入基线：** OVSP-RD-SDP-001《可靠设计软件改造开发方案》v1.0；OVSP-RD-ATP-001《可靠设计软件验收测试规范》v1.0；`requirements.json`；`traceability.csv`；`acceptance_cases.json`  
**审查对象：** 上述两份文档及其 PDF、需求与验收配套文件，以及当前 OpenVSP R2 代码基线

## 0 执行摘要

两份被审查文档已经建立了可靠的“目标合同”：把软件从概念原型改造成在限定适用域内、保留需求、完成确定性计算、显式表达未知、拒绝无证据结论的设计辅助软件。文档在状态语义、证据链、运行隔离、工程闭环和分阶段验收方面总体完整，可以作为后续开发的基线。

但它们是“开发方案和验收规范”，不是当前软件已完成的证明。审查确认：

1. 全部 AT-001 至 AT-062 初始状态均为 `NOT_RUN`，尚无可执行验收记录；
2. 当前 R2 代码已具备四布局、OpenVSP/VSPAERO、准则表和报告等原型能力，但没有实现文档要求的 `task_status / feasibility_status / evidence_status / recommendation_status`、运行仓库、指纹、证据门禁和独立验证；
3. 现有 105 项自动化测试只能说明现有断言通过，不能计为 62 项验收用例通过；
4. 当前四布局输出仍有飞翼航向稳定、鸭翼 `CMα`/失速、串列翼俯仰配平等警告，不能作为合格设计结论；
5. 文档范围以常规、飞翼、鸭翼三布局为主，当前软件另有串列翼能力，但验收文档没有串列翼专用需求/用例，必须明确“批准范围”和“实验能力”的边界。

本方案建议采用 **“先可信、再工程、再智能、最后独立验证”** 的路线，按文档的 M0–M4 门禁推进，不先扩张提示词或增加布局。当前最重要的工作不是让报告更肯定，而是让软件能正确说“通过、失败或未知”，并能证明每个结论来自哪个候选版本、哪个工况、哪个 run 和哪份原始文件。

## 1 审查范围、方法与结论

### 1.1 审查方法

- 阅读 PDF 全文并抽取文本，核对页数、章节、REQ/AT 数量与标记；
- 阅读同目录 Markdown、`requirements.json`、`traceability.csv`、`acceptance_cases.json`、`acceptance_record_template.json`；
- 将 PDF 与 Markdown 的 REQ、AT、`NOT_RUN` 标记计数互相对照；
- 将两份文档与当前 R2 代码的关键字段、测试和输出做差距检查；
- 抽查 PDF 页面渲染；生成完整页缩略图进行版式检查；
- 不执行文档内的验收用例，不联网，不调用真实凭据，不进行新的气动计算。

### 1.2 文档优点

1. **状态语义清楚**：文档把流程完成、工程可行、证据充分分开，不允许用 `ok=true` 代替合格结论；
2. **需求可追踪**：38 项需求、62 项验收用例、M0–M4 阶段和追踪表齐全；审查确认 38 项需求均有验收用例覆盖，62 个 AT 编号连续；
3. **反例优先**：大量 P0 用例针对旧版最严重的误判，包括旧文件复用、窗口最大值冒充失速、飞翼控制面退化、缺证据仍 pass；
4. **工程边界诚实**：明确 VSPAERO 低阶势流局限，明确 ENG_V1、VAL_V1 尚未批准，不用经验公式替代配平和独立验证；
5. **交付约束完整**：涵盖源码基线、运行隔离、离线边界、LLM 权限、报告证据链、干净环境重建和签署。

### 1.3 主要问题与建议

## 2 当前软件基线与差距

### 2.1 已经具备的原型能力

当前 R2 已具备：

- 自然语言/附件输入和规则解析；
- 常规、飞翼、鸭翼、串列翼四种布局的 OpenVSP 参数化建模；
- 机翼、平尾、垂尾、鸭翼、串列后翼的根部 Y 偏移和暴露面积裁剪；
- VSPAERO 极曲线和稳定性导数调用；
- 经验准则表、四布局样例、Word 报告和 105 项自动化测试；
- 翼型库、机身规则、MCP/CLI 入口和便携包。

这些能力是可复用的资产，但它们是**原型级**，不是文档所说“在批准适用域内可推荐的设计辅助软件”。

### 2.2 关键差距

| 需求范围 | 当前状态 | 主要缺口 | 优先级 |
|---|---|---|---|
| REQ-001～004 需求保留/单位/冲突/锁定 | 规则解析部分可用 | 失速上限与最小速度语义未真正独立；显式翼型/载荷/负角/冲突未完整锁定；无确认状态 | P0 |
| REQ-005 工程知识 | 经验规则和 criteria.py 存在 | 规则来源、版本、适用域、批准人未结构化；部分规则仍是硬编码阈值 | P1 |
| REQ-006～008 几何/控制/鸭翼 | 四布局建模和读回部分可用 | 无原生模型读回一致性门禁；鸭翼/串列翼参数未进入统一工具契约；控制面有效性未系统验证 | P0/P1 |
| REQ-009 坐标/参考点 | 部分导数已修正 | 无统一右手体轴适配器；重心变化后导数复用风险仍存在 | P0 |
| REQ-010～012 运行/失效/缓存 | 有输出目录 | 无 run_id、manifest、输入指纹、独立运行目录、正式 stale 失效传播 | P0 |
| REQ-013～014 气动有效域/失速 | 有 VSPAERO 极曲线 | `cl_max` 仍是扫掠最大值；无有效域和失速证据分层 | P0 |
| REQ-015～022 质量/配平/稳定性/性能/多工况 | 仅有估算和简化准则 | 无部件质量布置、完整惯量、实际配平、动力学矩阵、阻力分解、推进地图、任务积分 | P1 |
| REQ-023 三态门禁 | 有 pass/warn/fail 原型 | 无 `unknown` 聚合、无证据等级、无推荐门禁 | P0 |
| REQ-024～027 LLM/安全 | 工具有 schema 雏形 | 无 `expected_fingerprint`、预算、取消、进展检测、严格权限和路径边界 | P1 |
| REQ-028～030 优化/复算 | GA/解析优化原型存在 | 非可行性优先，缺跨布局公平口径，缺新进程最终复算 | P1 |
| REQ-031～034 报告/GUI/MCP | Word 报告和 GUI 已有 | 无逐项证据链、`unknown`/失败摘要、旧报告隔离、入口一致性测试 | P0/P1 |
| REQ-035～038 发布/独立验证 | 有便携包 | 无源码清单、干净环境重建、独立金样、不确定性、签署和限制声明 | P1 |

### 2.3 当前结论

当前 R2 适合继续作为 **技术原型和演示平台**，不适合作为“已可靠设计”的发布版本。现有四布局结果应作为诊断样例保留，不能作为工程金样或验收通过证据。

## 3 优化目标、范围与原则

### 3.1 目标

在 M0–M4 门禁完成后，使软件能够：

1. 完整保留并确认用户需求，包括硬约束、单位、符号、来源和冲突；
2. 对同一候选在统一坐标、质量、参考点和工况下完成几何、气动、配平、稳定性、动力学、操纵与性能计算；
3. 对每个硬约束输出 `pass/fail/unknown`，并给出证据、余量和原因；
4. 将任务完成、工程可行、证据充分和推荐状态分开表达；
5. 允许 LLM 在受控工具、预算和变量白名单内提出设计变更，但不能写指标、阈值或合格状态；
6. 通过独立验证数据、干净环境重建、验收记录和签署，发布限定适用域的版本。

### 3.2 范围边界

- 批准范围建议：常规固定翼、飞翼、鸭翼；串列翼作为实验扩展，不纳入本次完整功能签署；
- 适用域：低速概念设计；具体速度、高度、雷诺数、马赫数和重量范围由 VAL_V1 冻结；
- 不覆盖：适航批准、飞行放行、结构强度定型、气动弹性定型、制造工艺、复杂推进干扰、高速强分离、旋翼/VTOL；
- 任何未覆盖要求必须显示为不适用/未知/blocked，不能删除后宣称满足。

### 3.3 优化原则

1. **可信优先**：无有效证据不得输出绿色通过；
2. **单一领域服务**：GUI、CLI、MCP 和 LLM 工具共用同一计算与判定逻辑；
3. **确定性计算**：指标由注册计算服务产生，LLM 不直接写指标；
4. **版本化与可重现**：每个候选、工况、run、证据和报告都有身份与指纹；
5. **小步可验收**：每个工作包必须有 AT 用例、失败路径和证据归档；
6. **先冻结再扩展**：M0 前不继续堆叠布局、提示词或报告功能。

## 4 目标架构

```text
GUI / CLI / MCP / LLM tool loop
              |
      统一需求与确认服务（RequirementSet）
              |
      设计编排器 + 受控工具 + 预算
              |
      候选仓库 / Run Store / 证据仓库
              |
  +-----------+-----------+-----------+
  |           |           |           |
几何适配器   质量属性    配平/动力学   性能/任务
  |           |           |           |
  +-----------+-----------+-----------+
              |
      气动有效域 / 稳定性 / 操纵性
              |
      三态约束 + 证据门禁
              |
      可行性优先优化 → 最终独立复算
              |
      报告 / 签署包
```

### 4.1 建议新增模块

| 模块 | 职责 | 先决条件 |
|---|---|---|
| `requirements.py` | 类型化需求、单位、来源、冲突、锁定、确认 | schema 2.0 冻结 |
| `contracts.py` | 状态对象、ConstraintResult、聚合真值表、错误码 | 需求状态语义冻结 |
| `run_store.py` | run 目录、manifest、输入指纹、文件哈希、stale 传播 | 运行目录规范 |
| `mass_properties.py` | 部件质量、重心、惯量、装载包线 | 质量输入数据 |
| `trim.py` | 受限配平、残差、舵量/推力约束 | 质量、气动、推进数据 |
| `flight_dynamics.py` | 纵向/横航向矩阵、模态、特征值 | 配平点与惯量 |
| `performance.py` | 阻力分解、推进、任务能量、包线 | 推进/能源数据 |
| `validation.py` | 独立金样、误差预算、不确定性 | VAL_V1 |
| 改造 `criteria.py` | 只做约束汇总，不把经验比值当实际配平 | contracts.py |
| 改造 `report.py` | 只装配同版本证据，输出三种报告类型 | contracts/run_store |

### 4.2 不新增的内容

- 不一次性搭建空框架；
- 不新增未经批准的新求解器依赖；
- 不在 M1 前实现“大模型自动设计闭环”；
- 不把 Word 报告或截图作为计算正确性的替代证据。

## 5 核心改造包

### 5.1 需求保留与确认（REQ-001～005）

- 定义 `RequirementSet`：约束、目标、原文、来源、单位、确认状态、硬/软属性；
- 明确区分：
  - `stall_speed_max` 与 `minimum_operating_speed`；
  - `MTOW`、质量上限、估算值；
  - 显式翼型、载荷、角度符号、负值；
- 所有默认值必须有来源标签，不能覆盖已确认输入；
- 冲突输入返回 `conflict` 或待确认，不自动截断；
- 工程经验规则带 rule_id、版本、公式、来源、适用域和不确定性；
- 先完成 AT-001～005、AT-028 的解析/冲突/知识测试。

### 5.2 三态契约与证据门禁（REQ-023、REQ-031）

- 每个硬约束输出 `pass | fail | unknown`；
- 流程状态、可行性、证据状态、推荐状态分离：
  - `task_status`：completed / failed / cancelled；
  - `feasibility_status`：infeasible_for_evaluated_constraints / unknown / feasible_under_model / feasible_under_approved_profile；
  - `evidence_status`：complete / incomplete / invalid；
  - `recommendation_status`：diagnostic_only / analysis_only / engineering_review / verified；
- 聚合规则：
  - 有有效 fail → 不可行；
  - 无 fail 但有 unknown → unknown；
  - 全部 pass 但证据不完整 → 仅分析；
  - 全部 pass 且有批准 profile 证据 → 可进入工程评审；
- 旧 `ok` 字段保留兼容，但不得作为绿色合格标志；
- 报告摘要显示 fail/unknown 数量，不隐藏未知。

### 5.3 运行仓库、指纹与失效传播（REQ-010～012）

- 每个 job / candidate / revision / operating point / run 独立目录；
- 新 run 不读取旧结果；
- manifest 至少包含：输入哈希、需求版本、几何/控制、质量/惯量、推进/翼型数据、工况、坐标、参考量、求解方法、规则/profile 版本、源码版本；
- 输出验证：返回码、必需文件、输入关联、schema、有限值、工况覆盖、收敛、适用域；
- 模型/质量/重心/工况/阈值变化时，明确使下游指标、判定和报告失效；
- 缓存键不允许只用文件名或 GA 基因；
- 先关闭 P0 AT-014～018。

### 5.4 几何、控制面与参考点（REQ-006～009）

- 建模后必须从实际 OpenVSP 模型读回面积、展长、根梢弦、对称、暴露面积、位置和操纵面；
- 主翼/平尾/垂尾/鸭翼/串列后翼统一 schema；
- 验证飞翼升降副翼左右不退化；同相/差动混控有效；
- 鸭翼工具支持面积、展长、根梢弦、安装角、扭转、位置、翼型、控制面；
- 统一坐标适配器：几何层与领域层显式转换，力矩参考点转换使用完整力矢量；
- 重心变化后优先重新求解稳定性导数，不能只平移 Cm 曲线；
- 裁剪后的暴露面积与完整参考面积分开存储。

### 5.5 工程计算闭环（REQ-015～022）

- 质量属性：部件质量/位置/惯量、空机/载荷/电池、质量闭合和正定惯量；
- 实际配平：迎角、升降舵/升降副翼、鸭翼安装角、油门，检查限位、有效域和残差；
- 静稳定性与动力学：统一参考点、真实惯量、纵向短/长周期、横航向荷兰滚/滚转/螺旋；
- 操纵性：真实舵效、限位、速率、响应、侧风和必要失效状态；
- 性能：阻力分解、推进地图、爬升/巡航、能源和任务积分、多工况包线；
- 所有缺失数据返回 unknown，不用常数效率或经验惯量补成通过。

### 5.6 LLM、优化与最终复算（REQ-024～030）

- 工具按职责拆分：读需求、列缺项、查候选、提参数变更、建候选、运行指定工况、配平、评价约束、搜索可行候选、请求复算、生成报告；
- 所有写工具要求 `candidate_revision` 和 `expected_fingerprint`；
- 变量白名单、范围、锁定规则、预算、轮次、超时、取消；
- LLM 只能建议，不能写指标/阈值/可行性；
- 离线模式在 provider 边界实际阻断；
- 附件只作资料，防注入、路径穿越和越界读取；
- GA 采用可行性优先排序，目标必须真实支持；跨布局使用同一需求/工况/证据/预算；
- 最终候选必须新进程、新目录、冻结输入复算，不能使用搜索缓存。

### 5.7 报告与用户入口（REQ-031～034）

- 报告绑定同一候选版本、模型、质量状态、工况、run 和证据；
- 包含需求、假设、缺项、配平、稳定性、动力学、操纵、性能、逐条符合性、优化取舍、复算和限制；
- 支持诊断/分析/工程评审三类报告；
- Word/PDF 结构、逐页视觉和文字检查分开验收；
- GUI 显示待确认、未知、失败、旧报告过期；
- CLI/MCP/GUI 对同一 fixture 的状态逐项一致；
- MCP stdout 协议纯净，长任务取消/恢复可追踪。

## 9 风险与决策

| 风险 | 影响 | 缓解 |
|---|---|---|
| 独立气动/失速/推进数据缺失 | M2/M4 BLOCKED | 先列数据清单和责任人；缺数据保持 unknown |
