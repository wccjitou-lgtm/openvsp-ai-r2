文档编号：OVSP-RD-SDP-001  
版本：1.0  
编制日期：2026 年 11 月 2 日  
状态：待评审的开发基线  
配套文档：OVSP-RD-ATP-001 软件验收测试规范  
适用对象：产品负责人、气动总体工程师、软件开发、测试、集成与发布人员

## 1 目标与使用边界

本方案将 OpenVSP R2 从可以生成模型和报告的概念原型，改造成能够在批准适用域内，按自然语言输入生成候选、完成约束检查、解释计算依据并拒绝不可靠结论的设计辅助软件。开发的重点是需求执行、计算一致性、工程闭环和可验证的智能迭代，而不是增加报告的肯定措辞。

软件的成功标准不是一定生成一架飞机，而是正确区分以下结果：存在具备足够证据的可行候选；发现明确冲突；在给定预算内未找到可行候选；关键资料缺失或方法超出适用域。后三种结果也可以形成有用的诊断报告，但不得显示为设计合格。

本轮开发目标为可靠的概念设计辅助，不包括适航批准、飞行放行、结构强度定型、气动弹性定型、完整制造工艺或自动生成可直接试飞的飞机。用户输入这些要求时，应作为尚未覆盖的必要约束显示，不能删除要求后宣布任务满足。

初期验证对象为常规固定翼、飞翼和鸭翼。具体速度、雷诺数、马赫数、重量和高度适用区间由独立验证数据覆盖决定，不以一套经验范围代替批准边界。高速、强分离、旋翼、垂直起降、复杂推进干扰等未覆盖对象应明确受限。

本文件定义未来开发工作。除本文件明确列出的历史审查事实外，新增模块、字段、命令和测试均属于拟实现内容，不代表软件已经具备。

## 2 当前基线与已确认问题

### 2.1 基线资料

审查基线位于项目 `validation/audit_20261102_nl_layouts/`，主要依据为《审查与改进方案》、三布局 `layout_results.json`、参考点复算、控制面模型读回以及故障注入数据。历史运行环境为 Python 3.13.3 和 OpenVSP 3.51.3。

历史审查执行了 98 项 AI 非慢速测试、6 项 AI 慢速测试和 21 项 MCP 完整测试，并完成三布局真实离线流程。125 项原有测试通过仅证明原测试断言成立，不等于本方案新增能力通过。固定覆盖已有离线输出的一个原始测试当时未运行。

当前目录不是 Git 工作树，`patches` 为空，C++ GUI 源码由开发文档指向外部路径。开发启动前需要建立可识别的源码基线与文件哈希清单；未经单独授权，不提交、推送、发布或迁移用户已有项目。

### 2.2 缺陷转化为开发任务

| 基线问题 | 软件后果 | 本方案处理 |
|---|---|---|
| 失速上限未解析，海平面和负角度处理错误 | 输入工况被替换 | 需求类型化与边界回归 |
| 指定翼型和载荷未执行 | 输出与输入不一致 | 显式约束锁定与质量闭合 |
| 飞翼右升降副翼展向退化 | 操纵面模型与元数据不同 | 原生参数读回和混控验证 |
| 移动重心后沿用旧导数 | 稳定性结论矛盾 | 统一参考点及强制复算 |
| 扫掠端点被称为 CLmax | 失速判断随数值窗口变化 | 最大采样值与失速证据分离 |
| 求解失败读取旧文件 | 失败伪装成有效结果 | 独立运行目录及输出证据验证 |
| 新几何保留旧指标和报告 | 交付对象不一致 | 版本依赖与下游失效 |
| 缺数据仍总体 pass | 无证据结论被推荐 | 三态判定和证据门禁 |
| 离线 GA 进入 provider 调用 | 离线承诺失效 | 实际网络边界强制阻断 |
| 空报告仍肯定合理，CL 超域仍给性能 | 报告过度承诺 | 数据驱动结论和有效域校验 |

三布局旧参数和旧 L/D 数值是缺陷证据，不是新版必须逼近的金标准。新版引入配平、完整阻力或真实质量后，性能下降可能是计算更完整，不能通过恢复旧算法来追求数值一致。

## 3 需求管理与里程碑

### 3.1 唯一需求清单

`requirements.json` 是两份文档共用的需求编号、里程碑和数值容差来源。需求编号固定为 REQ-001 至 REQ-038；新增、拆分或删除需求必须同时更新开发方案、验收用例、追踪表和能力声明。

| 范围 | 需求编号 | 交付内容 |
|---|---|---|
| 需求与知识 | REQ-001 至 REQ-005 | 输入保留、单位、冲突、锁定规则和工程知识 |
| 几何与运行可信度 | REQ-006 至 REQ-014 | 模型读回、操纵面、参考点、版本与气动有效域 |
| 工程计算 | REQ-015 至 REQ-022 | 质量、配平、稳定性、舵效、动力任务与包线 |
| 判定与智能体 | REQ-023 至 REQ-030 | 三态门禁、工具权限、预算、安全、优化和复算 |
| 交付与验证 | REQ-031 至 REQ-038 | 报告、兼容、GUI、MCP、发布及独立验证 |

需求是可检查行为，不是模块名。某模块完成不等于该模块对应的所有需求已经通过验收。

### 3.2 阶段门禁

| 阶段 | 内容 | 出口条件 |
|---|---|---|
| M0 基线与契约冻结 | 冻结源码、数据、坐标、schema、能力范围和审批责任 | 关键接口与测试数据获得评审 |
| M1 结果可信 | 修复已确认问题，执行版本、证据和失败门禁 | 严重反例不再误判成功；缺工程证据仍不可推荐 |
| M2 工程闭环 | 完成质量、配平、模态、操纵和任务性能 | 模块通过解析与独立参考验证，形成多工况链路 |
| M3 智能迭代 | LLM 约束工具、可行性优先搜索、三布局公平比较 | 脚本回放、真实求解和最终复算贯通 |
| M4 独立验证 | 冻结适用域、误差预算、发布包和审批记录 | 配套验收规范全部必选项通过并签署 |

M1 允许交付更诚实的分析或诊断版，但不允许以 M1 替代 M2 至 M4，宣称已经可靠设计出满足全部条件的飞机。范围缩减版本必须在界面、API 和报告中声明未支持能力。

不在本文件承诺固定完成日期。工作包工期由开发负责人依据人员、现有源码状态、基准数据和试算成本评估，不能用未经测量的耗时作为发布承诺。

## 4 总体架构

### 4.1 分层职责

```text
GUI / CLI / MCP
      |
需求服务及确认状态
      |
设计编排器与有界 LLM 工具
      |
候选仓库及版本依赖
      |
几何适配器 -> 质量属性 -> 求解与配平
      |                       |
气动有效域 -> 稳定性及舵效 -> 动力与任务性能
      |
约束及证据门禁 -> 可行性优先优化
      |
最终独立复算 -> 报告与可追溯交付
```

所有入口调用同一领域服务和同一判定逻辑。MCP 不再维持另一套可以得出不同工程结论的计算简化版。入口可以有不同展示、协议和精简字段，但不能有不同的可行性含义。

LLM 不能直接赋值 `feasibility_status`、`verified`、计算指标或验收结果；只能读取证据，提出约束内的设计变更并请求受控工具。指标必须由已注册计算服务返回。

### 4.2 对现有代码的改动边界

| 现有文件 | 保留职责 | 改造内容 |
|---|---|---|
| ai/ai_design/designer.py | 兼容现有 Designer 外观接口 | 渐进委托需求、版本、计算与判定服务，去除混合状态 |
| ai/ai_design/vsp_bridge.py | OpenVSP 与求解器适配 | 模型读回、坐标转换、控制面设置、独立目录、进程与输出验证 |
| ai/ai_design/criteria.py | 约束结果汇总兼容入口 | 改为统一三态与证据判定，不把经验比值当实际配平 |
| ai/ai_design/ga_optimizer.py | 既有 GA 搜索结构 | 可行性优先、真实目标、完整缓存键、预算和最终验证 |
| ai/ai_design/agent.py | 模型交互和编排 | typed tool、变更审查、预算、取消及失败恢复 |
| ai/ai_design/tools.py | 工具注册与执行 | 输入边界、布局专用参数、版本前置条件和结构化错误 |
| ai/ai_design/config.py | 配置及路径读取 | schema 迁移、profile、能力和预算校验 |
| ai/ai_design/airfoils.py | 本地翼型检索 | 锁定选择、坐标及性能数据版本、适用域与来源 |
| ai/ai_design/report.py | Word 及数据报告 | 同版本证据装配、符合性和诊断模板 |
| mcp/openvsp_mcp_server.py | 协议、stdio 和 worker | 使用统一领域结果与失效规则 |

建议新增小型领域模块：`requirements.py`、`contracts.py`、`run_store.py`、`mass_properties.py`、`trim.py`、`flight_dynamics.py`、`performance.py`、`validation.py`。仅在对应阶段出现实际职责时新增，不一次性搭建空框架或占位实现。

GUI 改造预计涉及外部源码中的 `AIDesignWindow.cpp/.h`，但应先解决源码纳入交付和可重建问题。本方案不假定外部 C++ 树与发布包必然一致。

第一阶段沿用标准库、dataclasses、NumPy、已有测试和报告依赖。不为 schema 或流程强行新增运行时框架；确需新求解库或外部软件时，先确认许可、离线可用性、接口和独立验证。

## 5 数据契约

### 5.1 核心对象

| 对象 | 必选内容 | 不变量 |
|---|---|---|
| RequirementSet | 原文、来源、类型、单位、约束、目标和确认记录 | 显式输入不得被默认值覆盖 |
| OperatingPoint | 高度、速度、载荷、重心状态、环境与推进状态 | 标识唯一且与方法适用域匹配 |
| Candidate | 布局、几何参数、质量布置、操纵及推进配置 | 完整定义一架可比较的候选 |
| AnalysisRun | 输入指纹、方法版本、工况、目录、返回码和日志 | 一个 run 只对应一组冻结输入 |
| MetricEvidence | 指标值、单位、参考系、方法、有效域和原始文件 | 无证据不能升级为可验证结论 |
| ConstraintResult | 限制、实际值、状态、余量、证据和原因 | hard unknown 不能被汇总为通过 |
| DesignDecision | 任务、可行性、证据及推荐状态 | 计算完成与设计可行分开表达 |

内部数值统一 SI，计算字段使用完整精度，四舍五入仅用于展示。单位和坐标转换发生在边界适配器，不能在报告、优化器和智能体中各自重新解释。

### 5.2 需求表示示例

以下为拟新增 schema 2.0 示例，不是当前 `ai_job.json` 已支持的完整格式：

```json
{
  "schema_version": "2.0",
  "requirements_id": "mission-001",
  "revision": 1,
  "constraints": [
    {
      "id": "mission-stall",
      "quantity": "stall_speed",
      "operator": "le",
      "value_si": 20.0,
      "unit_si": "m/s",
      "hard": true,
      "source": {
        "kind": "user_text",
        "quote": "失速速度不超过20 m/s"
      },
      "confirmed": true
    },
    {
      "id": "mission-payload",
      "quantity": "payload_mass",
      "operator": "eq",
      "value_si": 5.0,
      "unit_si": "kg",
      "hard": true,
      "confirmed": true
    }
  ],
  "objectives": [
    {"quantity": "cruise_electric_power", "direction": "min"}
  ],
  "missing_required_data": ["propulsion_map", "mass_station_data"]
}
```

来源字段应支持附件文件哈希、页码或表格单元格定位、原始值、原单位和确认时间。LLM 提取置信度可以用于排序提问，但不能把高置信度等同用户确认。

同一句“25 kg”须明确指 MTOW、质量上限或估算值。“展弦比 8”是否允许优化变化应进入确认界面，不能由优化器悄悄改为自由变量。原始失速上限不能再经默认 `stall_margin` 隐式变成另一个需求。

### 5.3 结果表示示例

```json
{
  "schema_version": "2.0",
  "task_status": "completed",
  "feasibility_status": "unknown",
  "evidence_status": "incomplete",
  "recommendation_status": "diagnostic_only",
  "ok": true,
  "candidate_id": "cand-canard-001",
  "candidate_revision": 3,
  "input_fingerprint": "sha256-of-canonical-inputs",
  "constraints": [
    {
      "requirement_id": "mission-stall",
      "status": "unknown",
      "reason_code": "NO_VALID_STALL_EVIDENCE",
      "metric_id": null
    }
  ]
}
```

示例中的 `ok=true` 只保留旧版“任务产生交付物”的语义。新版 GUI 和自动化必须读取推荐状态，不能以 `ok` 作绿色合格标识。正式版本应执行 schema 校验，示例中的说明性指纹不能用作实际缓存键。

### 5.4 版本与指纹

指纹至少包含：规范化需求及确认版本、几何与控制混控、质量与惯量、推进和翼型性能数据、工况、参考系、求解方法与参数、适用域、判定 profile 和软件源码版本。

同一几何在不同重心、雷诺数、操纵状态或求解网格下必须是不同分析输入。不同工程阈值可以重用原始数值，但必须生成新的判定版本，不能复用旧“可行”标记。

候选谱系记录 parent、变更原因、参数差异和触发约束。禁止把大模型原始思维过程写入谱系；只保存可见决策说明、实际工具参数和结果引用。

## 6 需求与知识服务

### 6.1 提取与确认

对应需求：REQ-001、REQ-002、REQ-003、REQ-004。

解析顺序为原文识别、单位归一化、字段映射、来源绑定、冲突检查和确认。LLM 与规则解析结果冲突时保留两者和来源，触发确认；不能按谁最后执行就覆盖。

最低必要信息由计算能力声明决定。只提供巡航速度时可以进行有限几何初估，但缺推进图、质量位置或失速证据时，相关约束必须 unknown。允许用户确认假设继续探索，但报告必须保留假设，且不能超出证据等级。

校验规则包括：数值必须有限；重量、面积等满足合法域；载荷不能大于全重；最大速度不低于巡航；面积、翼展与 AR 保持关系；海拔 0 是有效输入；前掠、下反等负值保留符号；支持的单位有明确注册表。

### 6.2 工程知识记录

对应需求：REQ-005。

每条经验规则包含 rule_id、版本、公式、变量单位、原始来源、适用布局和工况、使用前提、输出不确定性、验证数据及批准人。可计算规则优先使用可测试函数，不让 LLM 临时发明公式后直接作为合格依据。

尾容量、翼载和经验惯量可用于生成候选或筛选明显异常，不替代实际配平、舵效或动力学计算。规则超出适用域时提供原因和可选方法，而不是继续截值。

本地翼型库需记录数据哈希和许可状态。翼型坐标与二维性能数据是不同资产；仅有坐标、厚度和名称不能构成可信 CLmax、黏性阻力或俯仰力矩证据。

## 7 几何与控制面服务

对应需求：REQ-006、REQ-007、REQ-008。

几何生成后必须从原生模型或导出文件读回关键参数；验证面积、展长、根梢弦、对称、暴露面积和部件位置。元数据只能记录预期值，不能替代实际模型。失败设置、截值、重复面和退化铰链必须报错。

主翼完整参考面积与裁剪后的暴露面积分开存储，参考量在候选内固定。三布局不能因为采用不同面积口径获得虚假的 L/D 优势。裁剪策略和机身是否参与求解必须进入方法说明及指纹。

飞翼升降副翼应以 OpenVSP 实际子表面和对称副本建立，并记录有效铰链、面积、组号及每个副本的增益。验证共同俯仰指令产生预期同相效应，滚转指令产生预期差动效应；不能用负 U 坐标表示另一侧。

鸭翼参数至少包括面积、展长、根梢弦、安装角、扭转、前后及上下位置、翼型、控制面和限位。工具查询、修改、重建、分析和报告均须能访问这些参数。对不能实现的结构安装位置，应保留几何警告或使候选不合法。

导入用户案例时保留基线结构和不可修改属性，明确“参数重建”与“原模型局部修改”两种模式；不能声称保留原模型，却仅抽取几个尺寸重新生成另一架飞机。

## 8 坐标与参考点规范

对应需求：REQ-009。

领域层采用右手机体系：x 向前、y 向右、z 向下；气动力、力矩、速度、角速度、惯量及导数都注明轴系。几何层可保留 x 向后、y 向右、z 向上的现有建模约定，但必须由适配器显式转换。

对于上述两套轴方向，旋转部分可表示为 `R_BG = diag(-1, 1, -1)`，坐标原点另行平移。实际 OpenVSP/VSPAERO 字段符号必须通过本地版本校验，不能仅根据变量名猜测。角度使用 rad 参与计算，界面可以显示 deg；角速度导数注明有量纲或按 b/2V、c/2V 归一化。

力矩参考点转换应由同一坐标系下的完整力矢量处理：

```text
M_Q = M_P + (r_P - r_Q) cross F
```

单位测试验证符号、量纲、正反转换和多轴力。建议重心变化后，稳定性和控制导数优先在新参考点重新求解；未经完整验证，不只平移一条 Cm 曲线就复用动态导数。

惯量必须对应质量重心，平行轴变换记录原点与偏移。状态矩阵前置检查参考面积、弦长、展长、轴系和重心版本一致。

## 9 运行仓库与求解可靠性

对应需求：REQ-010、REQ-011、REQ-012。

### 9.1 独立运行目录

```text
job/
  requirements.json
  candidates/<candidate-id>/revision-0003/
    candidate.json
    model.vsp3
    operating_points/<point-id>/
      runs/<run-id>/
        manifest.json
        input/
        raw/
        parsed.json
        validation.json
  final-verification/<verification-id>/
  reports/<report-id>/
```

结构是拟新增交付约定。run_id 在启动进程前生成，目录不得包含旧结果。所有文件路径必须解析在批准工作目录内；不以清空用户输出目录的方式获得“干净环境”。

### 9.2 求解器输出契约

有效结果须同时满足进程返回码、必需文件、输入关联、解析 schema、有限值、工况覆盖、收敛及方法有效域要求。文件时间可作为辅助证据，但不能单靠时间戳证明新鲜度；独立目录、输入哈希及文件哈希共同建立关联。

稳定性失败时可以保留成功的定常气动结果，但稳定性必须 failed 或 unknown，并使依赖稳定性的推荐门禁关闭。降级方法仅在批准适用域内启用，并明确方法变更及证据等级，不沿用原求解成功标签。

超时和取消必须结束本任务的进程树、关闭文件并记录残余输出无效；不能终止其他 OpenVSP 会话。原生错误不得因 Python 返回对象存在就被忽略。能够恢复的错误应限制重试次数，每次重试使用独立 run。

### 9.3 失效传播

几何或控制混控改变后，质量适配、气动、配平、导数、性能、判定和报告失效。质量位置变化至少使重心、惯量、配平、稳定性与性能失效。工况变化使相应工况结果失效。阈值变化只允许重判定，不允许伪造计算完成。

缓存仅保存通过输入校验的不可变原始分析或可重建派生数据。读取时核对所有指纹，不允许仅以 GA 基因或文件名作为缓存键。报告从冻结候选构建，不能混装搜索中多个版本的最优数字。

## 10 气动数据与失速处理

对应需求：REQ-013、REQ-014。

### 10.1 有效域

极曲线记录 AoA、Beta、Mach、Re、舵偏、重心、方法和网格覆盖。插值必须处于有效域内且满足数据质量要求；区间外返回 `OUT_OF_DOMAIN`，需要扩展求解或使用已批准模型，不能把端点 CD 当作真实巡航阻力。

同一 CL 可以对应不同迎角、状态或分离支路。存在多值或非单调时，不能先按 CL 排序后直接当单值函数插值；应依据配平状态、支路及有效域选取。

### 10.2 最大采样值与可信 CLmax

现有 `cl_max` 迁移为明确语义的 `cl_max_in_scan`。达到扫掠边界时记录 `peak_captured=false`。只有具备适用证据的失速模型才能输出 `clmax_effective`，并注明翼型到三维、配平、机身和控制面的修正依据。

改变迎角窗口不应单独提高失速证据等级。低阶模型的升力继续增长不能证明真实分离峰值，扩大扫掠不是修复失速模型的替代方案。

OpenVSP 官方 VSPAERO 培训将其定位为势流方法，并明确其对黏性效应和失速预测的局限。因此，项目需将低阶求解结果与失速证据分层使用，而不把求解器名称当作失速已经验证的理由。参考 R03。

需要引入二维极曲线、黏性修正或高保真数据时，登记数据版本、Re/Mach/转捩/粗糙度条件和许可。前翼先失速、翼尖失速和失速后操纵性等要求必须使用能够支持该结论的证据。

## 11 质量与配平

### 11.1 质量属性

对应需求：REQ-015。

输入每个设备或结构项的质量、位置、局部惯量、安装区域、变化范围和证据来源，区分空机、载荷、电池和任务消耗。显式载荷固定为用户值，经验比例只分配剩余预算；剩余质量为负时报告冲突。

计算总质量、质量重心和完整惯量张量，检查对称性、正定性及合理边界。非退化完整机体的动力学输入应具有正定惯量；理想点质量解析金样可以半正定，但不得直接用于需要逆惯量的完整动力学模型。无局部惯量时可用明确标记的近似，但必须做敏感性分析并限制飞行品质结论。

“为满足静稳定裕度所需的重心位置”只是一项布置约束。只有设备布置和质量预算能够实现该位置，才可将它纳入候选；不得直接把计算焦点减去目标裕度作为实际重心。

### 11.2 配平服务

对应需求：REQ-016。

配平输入为冻结候选、质量状态、工况、推进状态和控制限位。控制变量依据布局选择，可包括迎角、升降舵或升降副翼共同分量、鸭翼安装角和油门。结构安装角调整属于设计变量，不可与飞行中舵偏混淆。

在同一轴系内求解受力与力矩平衡，并检查全部限位、升力有效域和动力能力。小迎角近似可以用于初始化，但最终残差不能仅用 `L=W` 忽略推力方向和姿态影响。

最小二乘残差必须有物理归一化，输出收敛码、残差、限位余量和有效域。数值收敛但需要超限舵量仍为不可行；未收敛可能是求解或初值问题，不等于证明该布局无解。

M1 可以将配平能力标记 unknown；M2 必须提供可测试的实际配平服务。原有 `abs(CLα/Cmα)` 不再作为“能够配平”的通过证据。

## 12 稳定性与操纵性

### 12.1 静稳定性

对应需求：REQ-017。

在实际配平点和实际质量重心计算纵向及横航向导数，明确操纵面固定或自由的假设。静稳定裕度、Cmα、CLα 和中性点之间的关系需要满足同一参考约定，不能一个使用设计重心、另一个使用初始重心。

检查结果包括原始导数、归一化方式、工况、阈值来源和余量。静稳定目标不是单一全局固定范围，需由 ENG_V1 根据任务和控制方案批准。

### 12.2 动力学

对应需求：REQ-018。

构建配平点的纵向和横航向线性模型，纳入所用模型必要的质量、惯量、速度、重力、气动力和力矩导数。使用 NumPy 已有线性代数工具求特征值，不另写低可靠度特征值算法。

纵向应能区分短周期与长周期；横航向应能区分荷兰滚、滚转及螺旋模态。若模型包含航向积分状态，零特征值需按状态定义识别，不能一概判为失稳。实根、复根和近零根有明确分类容差及不确定性说明。

缺必要导数、质量或惯量时，不能默认零值后输出“通过”。经验二自由度近似可保留为估算模式，但不得与完整模型验证结果混在同一证据等级。

默认报告开环特性。需要以主动控制补偿不稳定时，必须显式输入控制律、执行机构和延迟模型，并独立验证闭环；不能因为计划安装飞控就接受未证明可控的候选。AVL 的公开能力说明可作为低阶定常配平与线性化分析的独立方法参考，而非本项目已经通过验证的证明，见 R02。

### 12.3 操纵与响应

对应需求：REQ-019。

通过实际舵偏或求解器支持的控制导数，建立升降、滚转和偏航效能矩阵，检查左右增益和耦合。舵偏步长需做敏感性与线性区检查；元数据中存在控制面名称不代表舵效有效。

检查任务规定的舵量余量、稳态滚转、响应时间、侧风及必要失效工况。舵机铰链力矩和速率没有证据时，应明确 unknown，而不是用尾容量常数代替执行机构能力。

## 13 性能与多工况

对应需求：REQ-020、REQ-021、REQ-022。

### 13.1 阻力及推进

阻力模型应明确诱导、型面、机身、尾面、干扰和附加阻力的来源及是否已被求解器包含，避免漏项和重复计入。黏性与机身效应缺失时，不得把当前薄面 L/D 作为完整飞机性能。

电动推进使用速度、转速或油门、电压、密度等适用条件下的推力、功率和效率数据。固定效率可作初估，但推进功率可用性必须有数据支持。涡喷等其他动力另立能力声明和数据接口。

巡航性能使用配平后的阻力及推进状态。爬升使用可用与需用推力或功率的差，并与速度、质量和高度一致；不得以“最大 L/D”代替所有性能目标。

### 13.2 能源与任务

任务按爬升、巡航、留空、返航和备份等已确认阶段积分。记录可用能量、可用电池容量、效率、储备、温度或放电限制以及变化质量。能量积分使用确定性计算，不能由 LLM 在报告中自行补一个续航数字。

没有推进图、能源容量或任务剖面时，航程航时判定 unknown。用户要求的储备是硬约束，不能在优化时默默取消。

### 13.3 包线覆盖

工况矩阵至少包含用户指定速度和高度，及任务要求的装载、重心前后限和控制状态。所有必选组合有状态，不允许仅取最有利巡航点代表整条包线。

工况数量、求解预算和降阶策略在运行前估算。采用代理模型筛选后，最终必选工况仍需独立复算；未覆盖组合须显式 listed unknown。

## 14 判定与不确定性

### 14.1 三态门禁

对应需求：REQ-023。

每个硬约束只采用 pass、fail、unknown 三种工程状态。计算异常通过 evidence reason 表达，不能把异常值当成合格数据。经验建议可以有 warn，但不能抵消硬 fail。

| 硬约束结果 | 总体可行性 | 是否可推荐 |
|---|---|---|
| 存在有效证据确认的 fail | infeasible_for_evaluated_constraints | 否 |
| 无 fail 但存在 unknown | unknown | 否 |
| 全部 pass 但独立验证不完整 | feasible_under_model | 仅分析，不能称可靠推荐 |
| 全部 pass 且批准 profile 的证据完整 | feasible_under_approved_profile | 可进入工程评审 |

“可进入工程评审”不等于飞行放行。一个工况 fail 即导致当前候选不满足全部任务要求，不能通过平均分掩盖。

### 14.2 无解语义

解析矛盾如载荷大于允许全重，可报告输入约束不相容。候选某项 fail，只证明该候选在所评估条件下不可行。GA 用完预算没有可行解，应输出 `NO_FEASIBLE_CANDIDATE_FOUND`，不能宣称数学意义上的全局无解。

### 14.3 不确定性

对应需求：REQ-037。

质量、重心、气动、效率和失速数据的重要不确定性须有来源、区间、相关性假设及传播方法。名义值通过但合理边界违反硬约束时，应报告脆弱方案，不授予稳健推荐。

缺少经验证概率分布时优先做确定性区间与敏感性分析，不用任意分布声称高可靠概率。数值精度、模型偏差和输入不确定性分别展示。

## 15 大模型工具与安全

### 15.1 工具契约

对应需求：REQ-024、REQ-025。

建议工具职责为：读取已确认需求、列出待确认项、查询候选与证据、提出参数变更、生成候选、运行指定工况、执行配平、评价约束、搜索可行候选、请求最终复算和生成报告。工具名称最终以接口评审为准，不能先在提示词中承诺未接入功能。

所有写工具需要 candidate_revision 和 expected_fingerprint，后端执行乐观一致性检查。变更必须在变量白名单、范围和锁定规则内，超限调用应结构化拒绝。模型不得修改用户硬约束、工程阈值或验证证据。

工具响应返回状态、指标证据引用、失败约束、归一化偏差、允许调整的变量、下一步可用操作和剩余预算。错误信息面向修复，不把进程堆栈或敏感文件内容全部送给模型。

LLM 循环同时限制轮次、求解次数、耗时、输入输出规模和外部调用预算。重复输入指纹且没有新增证据的调用应识别为无进展。取消和恢复须经过状态校验，不能直接跳到成功。

### 15.2 离线与不可信输入

对应需求：REQ-026、REQ-027。

离线策略在统一 provider 边界生效，覆盖 GA 建议、模型列表、降级和任何辅助调用。断言不发请求，而不只是缺少密钥。认证信息不进入日志、配置交付、缓存指纹、报告或 LLM 可见工具响应。

附件内容仅作技术资料，不能授权改写系统约束、执行命令、读取任意文件或外传。文件解析限制类型、大小、解压规模和读取范围，拒绝路径穿越与工作目录越界。

真实在线验收需单独批准服务商、发送数据、预算和密钥注入方式。默认 CI 采用脚本化 provider 或拦截网络边界，不使用个人环境中的真实凭据。

## 16 优化与最终复算

对应需求：REQ-028、REQ-029、REQ-030。

采用可行性优先排序：可行集优于已知不可行集；unknown 独立显示并优先安排补证据，不凭高 L/D 进入推荐榜。有限惩罚可指导搜索方向，但不能改变最终硬约束结果。

目标函数必须调用真实支持的指标。航时、爬升和最大有效升力若尚无模型，返回 `UNSUPPORTED_OBJECTIVE`，不能接受枚举却仍优化巡航 L/D。相同目标应写明任务、工况及单位。

跨布局比较使用同一需求版本、任务剖面、推进和质量假设、证据等级及预算规则。布局专用自由度可以不同，但参数边界和可修改范围要公开。参考面积可以随真实几何变化，比较指标不得因归一化口径不同而失真。

代理模型和低保真筛选必须记录预测与真实计算的区别。最终候选在新进程、新目录、冻结输入和全部必选工况下复算；不得读搜索缓存作为最终证据。复算与搜索差异超出已批准容差时，降级推荐并保留差异调查。

最终报告必须绑定复算后的实际模型文件、质量状态和证据，不拼接不同候选最好的静稳定、功率和 L/D 数字。

## 17 报告与用户入口

### 17.1 报告结构

对应需求：REQ-031。

报告必须包含任务与适用范围、已确认需求及假设、候选与参考量、质量布置、实际配平、多工况结果、静动态与操纵、动力及任务性能、逐条符合性、未知与失败、优化取舍、独立复算、数据来源和限制。

每个关键指标能追到 metric_id、run_id、原始文件、输入指纹、方法版本及批准 profile。无数据时显示“未验证”及原因，不用破折号配合“合理”等成功结论。

按诊断、分析、可进入工程评审三种报告类型生成。摘要必须显示未满足硬约束数量及 unknown 数量。图表标题和单位准确，不能把未配平曲线标为配平性能，也不能把窗口最大值标为已验证失速峰值。

Word 和 PDF 结构检查、文本核对及逐页视觉检查是不同验证。渲染工具缺失时报告结构可以通过，但排版项必须 blocked；不得只凭 ZIP 能打开即宣布报告验收通过。

### 17.2 GUI 与协议

对应需求：REQ-033、REQ-034。

GUI 首先显示提取的条件、来源和缺项，用户确认后启动工程计算。结果分开显示任务完成、可行性和证据状态。模型被修改后旧报告显示过期，不允许继续作为当前结果导入或展示绿色合格标记。

GUI 展示取消、预算、失败原因、未验证项和候选对比。旧结果需要显式选择才能查看，且必须标明版本。CLI、MCP 和 GUI 对同一 fixture 的约束状态逐项一致。

MCP stdout 保持协议纯净，工作进程和原生日志不得污染。长任务取消、超时及服务重启后仍保留证据状态，而不是只留下一个旧 report_path。

## 18 兼容迁移与发布

对应需求：REQ-032、REQ-035。

旧输入经显式迁移器升级，记录默认解释和未确认字段。保留任务、provider、输出路径等已有基本行为；新工程约束缺失则标 unknown，不把旧默认值说成用户输入。

结果继续保留必要旧字段，但新增 schema_version、能力和三种判定状态。对仍使用 `ok` 的旧客户端提供清晰升级提示。任何退出码变化、字段重命名和工具 schema 变化都需要契约测试与迁移说明。

打包应包含与源码基线对应的 AI、MCP、GUI 修改、模板、规则和公开可分发数据。外部商业翼型库不能悄悄打包；缺本地库应有可重现公开基线和明确能力降级。

依赖清单记录解释器 ABI、OpenVSP 版本、外部求解器、许可证、文件哈希和安装方式。在干净环境核对能否启动、运行三布局、生成报告并准确显示未配置能力。当前 Python 3.13 的成功不能证明任意 Python 都兼容本机原生 API。

发布前备份用户配置与产物，输出到新版本目录。包构建、安装、远程发布和全局变更按既有权限流程单独执行，本文档不授权这些操作。

## 20 验证策略与容差

### 20.1 验证层次

对应需求：REQ-036、REQ-038。

验证应分离算法实现验证、方法对真实对象的验证、模型输入质量和最终使用批准。NASA-STD-7009B 将模型使用的可信度、验证、确认和不确定性等作为模型与仿真管理内容；本项目借鉴其区分方式，不宣称通过该标准认证。参考 R01。

解析金样用于单位、质量、惯量、矩阵和能量计算。脚本 provider 验证编排与安全。真实 OpenVSP 验证几何和适配器。独立方法、风洞或可信公开数据用于物理精度，不能拿同一份代码产生的数据验证自己。

同一 VSPAERO 配置重复得到相同结果只证明重复性，不证明物理准确。三布局任务属于集成样例，不自动构成独立气动基准。

### 20.2 数值容差与工程阈值分离

NUM_V1 是本项目建议的软件数值验收默认值，不是适航要求：

| 项目 | 初始建议值 | 使用限制 |
|---|---|---|
| 标准单位换算绝对误差 | 1e-9 | 未四舍五入的单次标量换算 |
| 质量闭合 | max(1e-6 kg, 1e-8 × MTOW) | 规范化内部质量账目 |
| 几何读回 | max(1e-5 m, 1e-3 × 参考尺寸) | 几何长度读回，不适用于气动精度 |
| 配平归一化力残差 | 0.005 | 数值收敛门槛，仍需全部物理限位通过 |
| 配平力矩系数残差 | 0.001 | 以声明参考量归一化的必需力矩分量 |
| 解析矩阵特征值 | max(1e-8, 1e-6 × 参考绝对值) | 合适尺度解析金样，含状态定义 |

面积、惯量等不同量纲的容差应另行定义，不把“m 的绝对误差”误用于 m²。容差修改须记录依据和版本，不能在看到失败结果后随意放宽。

ENG_V1 包括静稳定目标及允许区间、模态和操纵限制、失速裕度、动力余量、能源储备等，需要气动总体及任务责任人批准。用户输入的硬阈值不得由工程 profile 静默放宽；profile 与输入冲突需确认或拒绝。

VAL_V1 包括独立参考数据、适用域、网格和步长收敛要求、各指标误差预算及比较方法，应先于候选验收冻结。未冻结 ENG_V1 或 VAL_V1 时，可完成软件层测试，但不能签署完整可靠设计功能验收。

## 21 三布局回归设计

统一任务用于检验软件是否保留和执行输入：25 kg MTOW、1000 m 海拔、25 m/s 巡航、失速不超过 20 m/s、载荷 5 kg、翼展不超过 3.2 m、AR 8、SM 目标 10%。布局是唯一变化项，是否锁定 AR 等条件须明确确认。

任务分三类数据包。第一类为历史反例，必须仍能指出旧问题而不是复用旧 pass；第二类为缺资料任务，必须明确 unknown 并列出缺项；第三类为经专业批准的完整正向金样，包含质量、推进、极曲线、控制限位、阈值和独立参考。

每类布局至少有一个正向样例、一个真实物理或数值拒绝样例及一个缺证据样例。不得强制三个自动生成结果都 pass；软件正确拒绝不可靠候选，也属于测试通过。

验收冻结模型不要求与旧模型外形一致，但锁定需求、原生几何、指标、报告和实际导入模型必须属于同一候选版本。详细用例与记录方式见配套验收规范。

## 22 风险与决策

| 风险 | 处理 | 责任 |
|---|---|---|
| 缺少独立气动或失速数据 | 限定能力，先补基准，不伪造精度 | 气动与验证 |
| 质量和推进输入不完整 | 保留 unknown 和建议补充清单 | 总体与产品 |
| 低阶方法超域 | 拒绝或切换经批准方法 | 气动 |
| 原生 API 状态与崩溃 | 短生命周期进程、独立目录、明确超时 | 后端 |
| 求解成本过高 | 分层筛选、可复用原始证据、预算和最终实算 | 优化与后端 |
| LLM 不稳定或工具循环 | schema、指纹、可回放测试和硬预算 | 智能体 |
| 旧客户端错误解读 ok | 迁移提醒、明确推荐状态、UI 契约测试 | 集成 |
| 外部源码或商业数据不随包 | 哈希清单、公开基线、许可和能力降级 | 发布 |

M0 需冻结的决策为支持任务范围、用户确认流程、坐标与数据 schema、首批独立基准、工程阈值责任人、外部依赖许可及发布能力声明。人员签名、批准日期和精度限值未确定前，不得自动填写“已批准”。

## 23 交付与变更控制

开发交付包括完整源码与补丁、迁移器、规则与公开基准、自动化测试、接口说明、运行 manifest、三布局证据包、报告模板、可重建包、限制清单和验收记录。
