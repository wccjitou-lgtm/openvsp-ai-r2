## 1 目的与依据

本规范检验软件能否忠实保留需求、执行确定性计算、拒绝失效证据、正确表达未知状态，并以可追踪证据支持限定适用域内的概念设计结论。三种布局用于验证同一软件契约，不是三套飞机设计建议，也不要求三个构型都取得工程可行结论。真实不满足约束的构型被正确拒绝，同样可以证明有关软件用例通过。

需求编号、需求所属里程碑和 NUM_V1 数值容差仅以同目录 requirements.json 为真源。本规范覆盖其中 REQ-001 至 REQ-038，阶段为 M0 基线与契约冻结、M1 结果可信与缺陷回归、M2 工程计算闭环、M3 大模型约束迭代与布局比较、M4 独立验证与限定范围发布。基线准备属于 M0，各用例的“阶段”按其映射需求填写，不另创需求编号。

缺陷反例取自 validation/audit_20261102_nl_layouts/审查与改进方案.md。历史 98 项非慢速、6 项慢速和 21 项 MCP 测试合计 125 项，只是旧版本运行记录；不能转记为本规范通过数，不能证明拟改造功能已实现。历史三布局 result.ok=true 也不证明配平、可行性或完整验证通过。历史 Word 逐页渲染未完成，不能记为排版合格。

本次交付只编写规范，不运行本规范用例、不联网、不调用凭据、不进行气动计算。以下 AT-001 至 AT-062 的初始执行状态全部为 NOT_RUN。执行后应在独立验收记录中登记结果，不以本规范中的预期值冒充实测值。

## 2 判定契约与阈值配置

### 2.1 状态含义

用例执行状态使用 NOT_RUN、PASS、FAIL、BLOCKED。缺环境、缺金样、缺批准阈值是 BLOCKED 的原因，不是 PASS；仅阅读代码或发现输出字段不能算行为验收完成。

单项 ConstraintResult.status 使用 pass、fail、unknown：有效证据证明满足为 pass，证明违反为 fail，缺失、失效、超适用域或无法计算为 unknown。硬约束合取时，只要有已证实违反项，整体属于不可行；无违反而存在未知项，整体为 unknown；全部满足才可进入模型内可行状态。总体结果细分为开发方案中的 infeasible_for_evaluated_constraints、unknown、feasible_under_model 和 feasible_under_approved_profile，不能以单个布尔值代替。仍须逐项保留未知项，不能因整体已有失败而隐藏证据缺口。

流程交付成功、工程可行和验证充分是三个独立概念。拟新增结果契约采用开发方案提出的 task_status、feasibility_status、evidence_status、recommendation_status，并在 M0 评审冻结；本文使用 run_id、候选版本、工况标识和 verified 等术语描述待验收语义，不声称当前代码已具有对应字段。缺失关键证据不得产生“已验证可行”结论。文中的总体 feasible/infeasible 仅为说明性的状态类别，实际记录使用上述精确枚举。

### 2.2 NUM_V1 软件数值容差

下列值逐字义对齐 requirements.json，只用于软件数值一致性，不是适航标准，也不是工程安全余量；配置当前仍属待评审提议。

- unit_abs：1e-9，用于归一化后单位数值的绝对误差。
- mass_balance_abs_kg：1e-6 kg；mass_balance_rel：1e-8。
- geometry_abs_m：1e-5 m；geometry_rel：1e-3。
- trim_force_normalized：0.005；trim_moment_coefficient：0.001。
- eigenvalue_abs：1e-8；eigenvalue_rel：1e-6。

组合误差判据拟在 M0 冻结为 |实测-参考| 不超过 max(绝对容差，相对容差乘 |参考|)，不得临时择取更宽判据。几何长度直接使用 geometry_abs_m，面积及无量纲几何恒等关系使用 geometry_rel，不把米制绝对容差直接用于平方米。单位换算使用 unit_abs；接近零的特征值使用绝对误差兜底。配平力残差以冻结的重量基准归一化，力矩残差使用冻结参考面积、参考弦长和动压形成的系数；三轴分量和符号须在接口契约中逐一明确。

除上述数值外，测试脚本的次数、预算、合成数据和注入错误值只是测试输入，不新增通用工程阈值。真源变化应先版本评审，再同步本规范和独立记录。

### 2.3 ENG_V1 与 VAL_V1

ENG_V1 由工程负责人批准任务范围、静稳定要求、模态与阻尼要求、操纵余量、失速证据要求、能源储备及失效工况。目标静稳定裕度 10% 是本任务输入，不代表所有飞机必须采用 10%，也不等于已经批准误差带。不得预设统一的静稳定、阻尼或舵效门槛。缺少强制工程阈值时，相关工程符合性为 unknown。

VAL_V1 冻结独立参考数据、来源授权、适用域、比较指标、误差度量与允许偏差，必须在查看候选输出之前批准。NUM_V1 不能替代模型精度验证；软件特征值求解与独立计算器一致，不证明气动模型或动力学假设正确。未获独立金样和工程阈值批准时，不得批准完整功能发布。

## 3 环境、数据与隔离

### 3.1 环境登记

每次执行记录操作系统、体系结构、Python 实际可执行文件及版本、OpenVSP/VSPAERO 二进制版本与哈希、NumPy 等依赖锁定清单、应用源码版本及本地修改摘要。历史审查使用 Python 3.13.3 和 OpenVSP 3.51.3，本机默认 Python 曾为 3.11.9；这些是历史信息，不是当前安装保证。执行者必须实测登记，不因命令写了 py -3.13 就认定环境一致。

单元与故障注入测试使用脚本化 provider、受控求解器替身及只含虚构信息的附件。替身只能证明状态机、解析和权限边界，不计作真实 OpenVSP、配平或独立工程验证。真实引擎用例必须保留实际模型、原始求解文件、标准输出、错误输出和退出码。GUI、MCP、CLI 使用同一后端版本和输入快照。

拟新增测试适配器、结果契约、工程金样仓库和执行入口均需开发后落地；本规范中的动作是验收要求，不是现有命令清单。运行记录应填写最终真实入口，不执行猜测的 CLI 子命令或工具名称。

### 3.2 数据分层与证据来源

需求基线由 requirements.json 及签署后的任务输入构成。历史 parser_probes.json、logic_probes.json、stale_stability_probe.json、stale_metrics_probe.json、alpha_probe_results.json、reference_point_probes.json 和模型文件用于复现旧问题，不作为正确值金样。

软件解析金样由手算换算和审定结构化需求构成；质量、惯量与矩阵金样由解析解或独立实现产生，独立实现不得导入待测计算函数。工程正向金样应来自有条件说明的实测、风洞、适用高保真结果或经审查的外部基准，不能由同一待测 VSPAERO 输出自证。独立来源必须记录获取方式、版本、许可、坐标、单位、参考点、雷诺数、马赫数、控制面状态和不确定度；引用某来源名称并不等于已取得数据。

M0 先冻结需求与软件解析样例，M2 前补充质量、配平及任务计算金样，M4 前冻结每个申报布局和功能范围的工程正例、反例、边界例。数据管理员计算原始文件哈希并只读保存，验证负责人先签 VAL_V1，候选输出随后生成。更改参考值或容差须留变更理由与重测范围，不得为迁就本次结果追认阈值。

### 3.3 三布局共享任务基线

共享输入文本为：“电动无人机，最大起飞质量 25 kg，海拔 1000 m，巡航速度 25 m/s，失速速度不超过 20 m/s，任务载荷 5 kg，翼展不超过 3.2 m，展弦比 8，目标静稳定裕度 10%。”分别仅替换布局名称为常规、飞翼、鸭翼，保留原始文本、归一化结果及人工确认记录。

AR=8 和 b<=3.2 m 同时为硬约束时，参考面积应满足 S=b²/AR<=1.28 m²。该代数结论可以独立校核，不表示低速性能已经满足。质量分解、质量位置和惯量、推进地图、黏性极曲线、有效 CLmax、任务分段、能源储备及工程阈值尚需补齐；缺哪项就将依赖它的约束标为 unknown，不能强制三个布局全 pass，也不能擅自采用默认 25~45 m/s 作为用户任务包线。

共享基线之外设隔离的正向工程金样。每个布局必须使用经批准、完整且来源独立的数据才能证明其正向工程链路；不能把共享基线缺资料造成的 unknown 改写成金样失败，更不能靠虚构推进效率或经验惯量把它补成通过。

### 3.4 文件隔离与运行方式

每次执行在新的专用验收根目录下分配会话、用例、候选、工况和 run_id 子目录。历史 validation/layouts、ai/outputs/offline_demo 及 audit_20261102_nl_layouts 原始产物只读，不清理、不覆盖。执行前记录保护目录的文件清单及哈希，执行后比对；有固定输出目录的旧测试未完成隔离前不得直接批跑。

现有 pytest 可作为低风险入口，示例中的 nodeid 必须替换为已确认存在且无固定输出副作用的单个测试。本命令不是本规范已落地测试集，也不在本次文档编写中执行：

```powershell
py -3.13 -X utf8 -m pytest <已确认存在的测试文件或nodeid> --basetemp <REPO_ROOT>\work\atp-20261102-session001\pytest-temp
```

pytest 可能清理 basetemp。示例目录必须经检查确认为本次新建且专用的临时目录，不得指向仓库根、用户目录、历史输出或任何重要目录。输出重定向与外部进程工作目录也须隔离；只设置 basetemp 并不能保护应用硬编码输出。

### 3.5 通用执行与失败处理

所有用例保存输入快照、预期断言、实际值、日志、版本和证据哈希；真实求解还须保存网格与工况。故障注入应位于可还原的测试替身或独立进程，不修改共享引擎二进制、全局环境或他人配置。

正向用例必须观察目标动作发生并检查数值、引用和状态；负向用例必须检查错误类别、拒绝位置、下游无副作用及旧结果未被冒用。崩溃、超时或空输出不是“按预期拒绝”。预算耗尽、取消、局部搜索无可行解只能报告“当前预算或搜索范围内未发现”，不得宣称数学意义上的全域无解。

## 8 缺陷分级与阶段门禁

### 8.1 缺陷等级

P0 仅用于误判放行、失效或伪造数据被采用、安全和权限绕过等严重问题。发现后立即阻断相关交付与完整发布，保留最小复现，不得用 warn 或报告注脚降级。用例优先级是执行顺序，实际缺陷等级仍需按影响判定，不能因某用例为 P1 就拒绝登记其中发现的 P0。

P1 为关键功能、可追踪性或数值契约不满足，显著影响限定域内工程工作流。P2 为不改变判定的展示、易用性或轻微文档问题；若排版遮挡失败状态，须按误判风险升级，不按外观缺陷处置。

缺陷记录包括复现输入、软件及数据版本、实际/期望、受影响需求、证据、责任人、修复版本和回归范围。关闭必须复测原例并检查相邻工况，不能只以代码评审通过关闭。争议项交由专业负责人和质量负责人评审，保留意见。

### 8.2 分阶段准入与退出

M0 退出需冻结 38 项需求来源、状态契约、测试隔离策略、NUM_V1 用法和数据责任人；记录尚缺 ENG_V1、VAL_V1 的内容与补齐计划。M0 冻结不等于工程验证完成。

M1 退出需 AT-001 至 AT-027 在适用版本执行并评审，所有 P0 关闭；结果身份、旧证据防误用、三态门禁和离线边界不得延期。允许工程能力仍标 unknown，但不得宣传这些能力已合格。

M2 退出需 AT-028 至 AT-040 完成，且具备获批工程输入、配平、质量惯量、模态与任务链的正反例。缺正向金样不能仅凭错误处理完善宣布工程闭环完成。不能把范围缩减用作掩盖已申报能力未验证。

M3 退出需 AT-041 至 AT-054 完成，并复查 M1/M2 受影响回归。脚本化 provider 可证明受控工具链，不证明真实服务商的质量和稳定性；若未来申报在线服务能力，另需明确授权后的专项验证，本规范不要求凭据调用。

M4 退出需 AT-055 至 AT-062 完成以及全部强制需求具备有效证据，发布范围、独立基准、ENG_V1 与 VAL_V1 获准。未关闭 P0/P1 不允许完整功能发布；P2 是否暂缓须有书面风险接受、责任人与期限。NOT_RUN 和 BLOCKED 不计通过率分子，也不从强制覆盖分母删除。

限定范围发布只能排除明确不支持且不会被用户误用的能力，由批准人签署限制、GUI/报告披露和保护措施；不能把未知项改名成不适用以绕过验收。软件验收批准只适用于声明的概念设计域，不是飞机结构强度、气动弹性、适航或试飞批准。

## 9 单条执行记录模板

每个用例每次执行独立留记录，重试不覆盖首个失败。以下为拟新增记录格式，不声称当前系统已经支持自动生成；证据路径只允许指向本次受控目录或只读冻结来源。

- 记录标识：会话 / AT 编号 / 执行序号。
- 用例版本、需求编号、阶段、执行优先级及实际缺陷等级。
- 执行人、复核人、开始结束时间及本地时区。
- 应用版本、修改摘要、环境快照、工具版本与哈希。
- NUM_V1、ENG_V1、VAL_V1 版本与审批引用。
- 原始输入、确认需求、数据来源、样本哈希及随机种子。
- 候选版本、工况、run_id、输入哈希与参考点。
- 实际入口及参数、逐步动作、故障注入位置与恢复方式。
- 预期断言、实际数值、误差、工程三态与流程状态。
- 执行结果：NOT_RUN / PASS / FAIL / BLOCKED，填写唯一值。
- 证据清单、路径、哈希、页面或日志定位。
- 失败或阻塞原因、缺陷编号、影响范围与临时保护。
- 重测所用版本、原例结果、相邻回归结果及关闭审查。
- 未验证内容、残余风险和最终复核意见。

记录中的 PASS 只说明该用例期望成立。例如预算停止用例通过，不说明设计可行；缺证据用例正确输出 unknown 而通过，不说明对应工程能力完成验证。汇总须同时展示软件用例结果、需求证据覆盖和工程可行性，不使用一个“通过率”混合三种含义。

### 10.2 专业确认与发布限制

当前待专业确认：三布局有效失速/CLmax 与黏性极曲线来源；实际部件质量、位置、惯量及装载包线；推进地图和能源任务；坐标、导数、参考点及配平残差定义；静稳定、模态、操纵和能源余量的任务化阈值；独立金样和收敛误差；不确定性区间及关联性；包重建、报告渲染和真实接口入口。
